# PACE 界面重设计（2026-10-20）

> 两次视觉方向被否后的第三次。这次不是换色，是换视觉语法、信息架构与核心交互。

## 1. 为什么前两版被否

| 版本 | 做了什么 | 为什么不够 |
|---|---|---|
| v1 深色 | 深底 + 靛蓝 | 深色与「整天开着看数据」的使用场景矛盾 |
| v2 暖纸浅色 | 暖灰 + 深青 + 卡片 | **只换了色相，没换语法**：52px 顶栏、圆角卡片、`shadow-panel`、表格优先，全部保留。远看仍是「2015 管理后台换皮」 |

v2 的四个具体失败：

1. **纸的语义错了**。纸代表「已完成、可归档」；PACE 的核心对象是**正在运行的进程**。暖纸把产品讲成一份报表。
2. **克制做成了没有焦点**。所有元素权重接近，深青几乎只出现在选中行。结果是安静，不是精确。
3. **界面里没有「智能体」**。对话页是气泡，运行页是表格，没有任何东西在动、在推进、被观察。
4. **暖米色与编辑器并排会发脏**，且深青是 B2B 最安全的默认色——安全即无观点。

## 2. 视觉方向：校准台（Instrument Panel）

**论点：界面是一台校准过的仪器，安静到只剩正在发生的事有颜色。**

- **冷中性**替代暖纸。`canvas #F3F5F7`、`surface #FFFFFF`、`panel #EAEEF2`、`line #D9E0E6`。
- **信号色只有一个**：`#C2410C`（橙）。它只表示「正在发生」——运行中的行、焦点环、live 点。
  没有任务在跑时，整页是灰的。这一条同时回答「这是什么产品」和「此刻发生了什么」。
- **墨色主按钮**（`#12171C` 实底白字）承载主要动作，橙不用于按钮。
- **字体**：IBM Plex Sans（400/500/600）+ IBM Plex Mono（数字、ID、耗时、成本、代码）。
  尺度 11/13/14/16/21/34。等宽不是装饰，是「这是测量值」的信号。
- **无卡片表面**：区块用通栏 1px 横线分隔，只有弹层/抽屉/菜单拥有白底与阴影。 радиус 2px。
- **记忆点**：全屏唯一的高饱和色，是正在跑的那一行。

## 3. 信息架构

从「按实体平铺」改为「按任务」：

| 导航 | 服务的故事 | 默认屏 |
|---|---|---|
| **工作台**（置顶） | US-4.2、US-3.5 | 首屏是「需要处理」：失败运行、待批准、从未测试的 server |
| **对话** | US-3.1–3.4（最高频） | 直接给 composer，不拦在「先选智能体」 |
| **运行** | US-3.5 | 按会话分组，失败置顶 |
| **构建** | US-1.x、US-2.x | 二级：智能体 / MCP Servers / 技能 |
| **系统** | US-4.3、US-4.4 | 二级：健康 / 审计 |

理由：构建合并同一件事的两半（把外部能力变成智能体能读的文件）；运行独立，因为它是高频诊断面。
**评估没有用户故事，降级为智能体详情里的一个区块**，不再占一级导航。

## 4. 核心交互（对话与运行详情）

### 对话
- 空态：智能体名 + 能力摘要（绑定 N 个 server / M 个工具 / 权限模式）+ 最近一次运行，输入框自动聚焦。
- 助手文本不用气泡，占满列宽；工具调用是**单行工具行**（状态图标 + 名称 + 参数预览 + 耗时），
  默认折叠，点击原位展开参数/结果两栏。
- 连续工具收进「执行 5 个工具 · 8.2s」的组。
- 子智能体：父行显示「子智能体 · 6 次调用 · 2 失败」，子调用只展开一级，行首 `↳`，不再逐层缩进。
- 审批卡片在**被拒工具的原位置**，不在消息流末尾；按钮写「批准并继续（新一次运行）」。
- 输入框上方常驻状态条：`● 第 3 轮 · 正在调用 search_orders · 00:42` + 停止。
- 结束后答案下方：`完成 · 3 轮 · 18.2s · 2,341 tok · $0.041 · 查看详情`。

### 运行详情
- 顶部粘性摘要条：状态、智能体（可点）、模型、开始时间、耗时、轮次、成本、token；
  右侧「停止」/「用同样输入重跑」/「在对话中打开」。
- 左栏步骤树（400px）：序号、类型、名称、单步耗时、状态、按最大值归一化的 3px 时长条。
  **「卡在哪」由时长条直接回答**。
- 右栏检查器：面包屑 + 标签页「参数 / 结果 / 错误 / 原始事件」。参数与结果分开（当前混在一个块里）。
- 选中步骤写入 URL `?step=`，可分享、可刷新。

## 5. 配置页

**心智模型：不是编辑数据库行，是组装一个会写盘的工作区。**

字段必须标注目标位置：`→ CLAUDE.md` / `→ .mcp.json · mcpServers.<name>` / `仅运行时`。
因为 `permissionMode` / `maxBudgetUsd` / `timeoutMs` / `maxThinkingTokens` **不进文件**，只传给 SDK。

### 智能体
左列表 + 右编辑器，内部**分区 + 粘性节导航**，不是长滚动：

1. 身份（设一次，折叠）
2. 行为（高频）：系统提示词、模型、effort
3. 能力（接线时高频）：Servers / 技能 / 子智能体，每项显示「将获得 N 个工具」
4. 权限（危险，默认折叠）
5. 运行限制（设一次，折叠）

文件预览改为**内联片段**（草稿实时渲染），完整文件仍在 Tab。

### MCP Server
三种 kind 是同一个对象的三种接入方式：一个列表、一个详情页、一个创建流程（第一步选来源）。
generated 的工具表是一级信息，点行开抽屉编辑，含「试调用」。

## 6. 本轮不做的

以下是设计诊断出的真实问题，但需要后端接口或较大改动，单独排期：

- Server 详情页与 `server → agents` 反向索引（需新 API）
- 未保存草稿的连接测试（需后端支持）
- 工具试调用（需后端支持）
- 运行时的模型/版本快照（`agent_runs` 缺字段）
- 事件流里的单步耗时（重连后丢失，运行详情改为读 `agent_runs`）
- Markdown 渲染（需引入依赖）
- 评估并入运行表
