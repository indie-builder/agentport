## 当前结论

PACE 已有知识资源管理、摄取/索引/混合检索、专家受控工具接入、Wiki 草稿发布和外部同步的基础链路，但不能称与 WeKnora 核心能力等价。差距分成三个层次：内容与证据处理的行为问题、已有模块的业务深度不足、真实服务与效果未验收。此前“完成范围内实现”不应扩张为“完整复刻/生产可用”。

### 1. 优先处理内容与来源正确性

| 项目 | 已有能力 | 仍有的问题与用户影响 | 建议 |
|---|---|---|---|
| 人工分块与引用 | 可以改正文、重建向量、保存文档版本 | 修改直接覆盖同一 chunk，未留独立修订；原页码与版本仍在，命中人工新句却可能显示原件页码、打开旧正文 | 贯通人工标记、使旧定位失效，保存最小修订记录；外部更新/重解析不得无提示抹掉人工改动。详见检索报告“引用定位与人工修改” |
| Feed 全文保留 | 解析三种 Feed，定时摄取，滚出窗口不当删除 | 全文抓取失败会回退摘要，再按内容变化摄取；已有全文可能被摘要替换。无标识条目还有身份回退问题 | 失败保留上次成功正文；区分未变、失败和真正更新；补稳定身份回退。详见来源报告第1项 |
| 无答案与检索状态 | 中文关键词+向量、RRF、可选 rerank、空结果界面 | 向量候选缺少最低相关性过滤，库外问题也能得到无关块；rerank 失败和向量降级未完整传到 MCP | 用有答案/无答案样本校准门槛，返回实际召回路、重排结果和分数来源；最终回答仍交现有 Agent |
| 专家包跨宿主使用 | 平台内运行和同实例回导可恢复知识绑定 | 包只有 HTTP URL/token 占位，端点却要求 run ID 和平台签发短期 token，外部宿主没有完整授权路径 | 先准确标明边界；要满足可移植目标，应补受库范围约束且可撤销的外部授权流程，不能导出运行 token。详见平台报告第1项 |

以上均有静态调用链依据；不把它们包装成已运行复现的生产故障。独立[五组定点复核](knowledge-parity-verification.md)还确认以下目标内 P1 问题：

- **来源范围收缩不立即生效：**只替换范围配置，旧文档仍可搜/read；不能指望下次同步一定补救，删除对账有完整枚举与开关条件。
- **完整重建可能恢复已撤权内容：**默认 rebuild 遍历包括 disabled 在内的文档，摄取成功后无条件设 ready；来源仍 disabled 或 delete-keep 后已不存在也可发生。这是顺序路径，不依赖并发。
- **人工修改保护不一致：**源正文变化或默认完整 rebuild 可替换当前人工分块；专用 reprocess 有确认但仅检查前200块。旧版本一般仍留存，不能称彻底删除全部人工历史。仅补向量的 chunksOnly 路径不重新解析。

来源 disable/delete 的正常分支已会停用/删文档，暂停抓取也不自动等于撤权；问题应限定在上述具体路径，不把已修分支一概说成失效。

### 2. Wiki 的差距是知识组织深度

官方代码不仅生成一篇总结：还按文档抽取实体/概念、稳定页面身份、跨文档归并、规划目录、维护索引与入链/出链、记录来源贡献、做 lint 和部分内容损失检查。这里仍不能推论官方生成的事实必然正确。

PACE 当前是对指定页面使用 SDK search/read/save_draft，自动首次建立 overview；已具备追加草稿、人工编辑、发布/回退、版本冲突与来源有效性校验。来源变化会标 stale 并可触发新草稿，**不等于已从已发布正文撤回来源贡献**，也不等于已生成完整主题网络。

建议仍用 Claude Agent SDK 和现有知识任务：补页面计划/同名实体复用、结构化目录/链接、来源贡献与差异审阅，逐步补断链/失效引用检查。保留人工发布保护；不移植官方另一套智能体运行循环。双侧证据与细分差异见来源报告第3–5项。

**还缺 Wiki 到专家的消费闭环：**当前知识检索和 MCP read/list 仅消费原始文档，不消费 Wiki 正文。管理员可以查看带 stale 状态的已发布页，不能因此声称它仍被 Agent 召回；若 Wiki 要成为专家可利用的知识层，需要明确接通已发布/有效版本的读取与引用。

### 3. 外部同步目前覆盖首批来源的一部分

| 来源 | PACE 当前边界 | 与官方代码的主要差异 |
|---|---|---|
| 飞书 Wiki/Drive | docx、部分文本和递归分页；普通表格有渲染路径 | sheet/bitable/附件/二进制不完整，混合空间可能被单个不支持对象阻断；长 docx 截断边界需显式表达。官方也非支持所有飞书对象 |
| GitLab | 项目/ref/paths 内文本文件、完整树分页、删除对账 | 官方有更多文件格式与 commit compare；PACE 每轮全树/正文抓取后判等，二进制和 MIME 尚未统一进解析管线 |
| RSS/Atom/JSON | 已有解析、调度、来源追溯和窗口删除区别 | 条目增量信号利用、全文抓取失败保留、身份回退不足 |
| 来源配置与日志 | 有手输范围、配置检查、同步 run、重试/取消/对账 | 缺实际只读试连、远端资源导航、逐项错误持久化；“updated”计数包含未变条目，不能直接当真实变动数 |

GitLab Wiki/Issue/MR 两侧此次检查的连接器均未实现，不能列为“官方已有而我们漏了”。两侧连接器读取应用凭据可访问的内容，都不能仅凭接入品牌宣称完整继承所有企业用户 ACL。PACE 当前是单管理员共享资源和运行绑定隔离。

建议先统一连接器 bytes/MIME→已有 parser 的路径，复用已接入的 Docling；再用 commit/对象编辑时间减少重复读取，并补导航、试连和逐项日志。仍复用现有 BullMQ/Redis、知识来源和同步记录，不新增连接器运行底座。

### 4. 解析、检索和查看还有深度差异

- **检索上下文：**已有 heading，但 embedding/关键词/重排主要用块正文；缺父子块/邻块扩充。先利用已有标题与 heading，再以失败样本决定邻块策略，无需先移植整套复杂分块算法。
- **证据定位：**解析器有部分结构信息，但适配和存储后主要剩页码；引用打开整篇 Markdown，PDF 页内/表格行列/幻灯片定位不完整。应优先保留已有解析定位贯通查看器，不编造未知位置。
- **检索测试：**界面主要输入问题，无法充分诊断实际召回路、重排 outcome、不同分数语义；后端已有的过滤与 rerank 选项也未完整开放。
- **原件与批量管理：**有批量上传、单文档管理与 Markdown 查看/原件下载；缺部分批量移动/标签/删除/重处理及原 PDF 内联预览。上传保留路径名不等于目录树恢复。
- **模型与格式：**1024 是向量维度，分块主要按字符；缺与当前服务版本绑定的支持矩阵，不能以“上传成功/请求了 Docling”保证所有格式可解析。无需为形式上的多模型支持增加第二套存储。

对应证据见检索报告各表格与平台报告第3–4项。

### 5. 交付与运行边界

平台现有 metrics 只统计聊天队列，知识队列积压/失败不在该指标内；应扩展当前指标而非加新监控平台。任务页面、重试、取消、调度和重启对账均已存在，不能重复列为缺失。

知识 ZIP 有 64 MiB 压缩/128 MiB 展开/5000条目限制，导出导入采用内存缓冲；持续增长的库不保证都能整库打包。大库完整搬迁应明确使用 DB+知识卷备份；是否改流式包由实际规模决定，不因理论规模直接重写。历史备份演练有证据，但不证明主栈部署、restic 或任意规模都已验收。

真实 Docling/OCR、真实 embedding/rerank/Wiki 模型、真实飞书/GitLab账号与范围、实际主栈镜像/卷升级尚未验收。确定性 HTTP 夹具与 SDK 协议 mock 证明装配和生命周期，不证明 OCR 准确率、召回率、生成质量、限流容忍度或费用可控。

### 6. 不应为了追齐功能表而复制的部分

- 继续使用 PostgreSQL/pgvector、当前持久卷、BullMQ 和 Claude Agent SDK；不复制 Go/asynq/多向量数据库或第二套 Agent/聊天循环。
- 智能体仍以官方 `.claude/` 文件定义；企业语料独立 DB/文件卷不是违反文件原则。需要完善的是导出后的真实可连接性。
- 单管理员当前不要求新增多租户/RBAC；完整企业 ACL 若成为目标需单独明确。
- FAQ、图谱、图片语义检索、音视频转写和更多连接器属于参考项目较丰富的能力，未全部被用户逐项纳入本批范围。文档 OCR/图片展示与图片语义检索分开，不能混为一项。
- 腾讯 Memory 持续暂缓，现有原生记忆保留。

## 推荐推进次序

1. 先收口人工编辑/来源身份、Feed失败保留、来源主动撤销/范围变化的行为，以及相关回归用例。
2. 并行做真实文档/模型质量验收与检索诊断；首批飞书/GitLab对象补齐及二进制入库也可并行。共享依赖是统一的文档内容/定位与来源结果契约。
3. Wiki 基于稳定来源与引用补知识组织和贡献更新；页面编辑/版本审阅可并行，自动维护依赖前面的来源身份。
4. 完善平台内专家使用、批量管理/原件定位、知识队列指标和可操作的运行日志；外部宿主授权移出当前建设范围。新增 GitHub 同步与参考官方的多模态接入按最新范围补充。

这是优先级建议，不把用户的完整建设目标拆成可省略的演示范围，也不表示本轮已开始修复。
