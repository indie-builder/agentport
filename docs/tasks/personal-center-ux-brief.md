## 核心问题

现有六页主要对应资源和接口：资料、记忆文件、review运行、session、share、run。页面完整展示这些对象，但用户完成任务的过程未被表达清楚：

- 维护偏好和从对话提炼偏好是同一目标的两条路径，目前缺少关联。
- 原“历史回顾”实际是生成、审核和采纳记忆提案，旧名容易与聊天历史混淆。
- 提案详情先来源、理由、证据，较后才到修改前后；采纳决策所需的变化不够靠前。
- 安全页让改密表单成为首要区域，用户检查登录记录时先遇到另一项任务。
- 分享缺少直接打开已分享内容的入口，确认内容需复制后另行访问。
- 使用记录以运行ID起始，整行点击可能去聊天、回顾或运行详情，用户无法预见去向。

## 用户目标与入口结构

保留六个独立目的地，按目的分组；分组只承担导航关系，不增加概况页或重复数据。

| 目的组 | 目的地建议 | 用户要完成的事 |
|---|---|---|
| 与专家协作 | 个人记忆 | 让专家了解自己的长期信息与协作偏好 |
| 与专家协作 | 记忆提案（原“历史回顾”） | 从过去对话提炼内容，判断后写入适当目标 |
| 工作记录 | 我的分享 | 找到已分享的成果，确认内容、复制或停止分享 |
| 工作记录 | 使用记录 | 找回工作、定位失败、查看本人消耗 |
| 账号 | 个人资料 | 修改别人看到的姓名，核对身份 |
| 账号 | 账号安全（原“安全与会话”） | 检查登录，撤销不需要的会话，按需修改密码 |

分组顺序可按任务假设推荐，默认进入个人资料暂保持，避免未经验证引入概况仪表盘或强制改变落点。专家共享目标仍沿用权限，不因为入口在个人中心变成私有内容。

## 动线1：让专家了解我

**用户故事**：当专家反复问我的背景或不遵循协作偏好时，我希望能确认它会收到哪些长期信息，补充后继续工作。

**主路径**：查看当前记忆 → 选择编辑 → 修改 → 保存 → 明确已保存且下一轮会带入 → 继续工作。

**另一条路径**：我不知道怎样归纳 → 从对话整理 → 选择来源与目标 → 生成提案 → 审核 → 采纳 → 查看更新后的记忆。

个人记忆的信息层级：

1. 当前已保存的内容；短句说明“每轮对话会带入这些长期信息”，这是影响用户决策的产品事实，不能只呈现Markdown技术标签。
2. 明确“编辑”入口；阅读态优先易读的正文，编辑态复用现有SourceEditor。编辑时保存/取消与未保存状态就近出现，保留草稿与冲突恢复。
3. “从对话整理”作为同目标的另一种方式，连接已有回顾创建流程；不宣称自动提炼。
4. 版本历史作为恢复入口，默认按需展开，不在空记忆旁展示一整列空版本。下载留在次操作。
5. 保存成功后明确下一轮生效语义；从具体工作进入时返回原上下文，直接访问时提供“去对话”而非编造上次会话。

**空态**：帮助用户选择“自己填写”或“从对话整理”；可提供不会保存的示例占位，但不捏造已记住的个人事实。不把单份Markdown拆成多份独立数据或固定分类表。

## 动线2：从过去对话得到可采纳的记忆

**用户故事**：一次工作结束后，我想把值得复用的结论留下，并在写入前确认内容、依据和影响范围。

**主路径**：选择哪些对话 → 确认记到哪里与由谁整理 → 生成 → 查看变化 → 核对依据 → 采用/拒绝/重新生成 → 到目标查看。

创建流程按任务展开，而不是一次把技术选项摊满：

- 选择来源专家及其本人会话；由于现有查询按专家取会话，专家选择是来源选择的真实前置依赖，不能用伪造跨专家列表跳过。
- 确认目标：默认个人记忆；有相应权限才提供专家记忆/规则及文件选择，并明确它们是专家共享目标。执行审核的专家独立标注，不能混同来源专家或目标专家；只有真实选择才提交，不悄悄替用户作决定。
- 补充要求可选，提交前摘要列出所选来源、目标与执行专家。现有能力是选择最多10段来源，不是日期区间选择。

提案列表围绕处理状态组织：待审核优先，生成中与已处理可切换查看；执行状态与采纳状态分别表达。使用现有run/decision数据派生列表视图，若服务端当前分页无法覆盖所有分组，需说明“当前已加载记录”或补齐真实查询，不能伪称全局待审核数。

审核详情的信息顺序：

1. **写到哪里、会改什么**：目标范围，以及修改前/后的正文；涉及索引时连同索引变化展示。
2. **为什么建议这样改**：理由与证据归因，明确用户事实/已确认决定/助手建议，来源可回原对话。
3. **作出决定**：采用、拒绝、重新生成；没有变化时显示“无需变更”，无采用动作；权限不足明确只读。
4. **完成反馈**：已采用及查看目标；拒绝不修改内容；冲突说明目标已经变化、当前提案不能直接覆盖，提供重生成。

采用动作必须在用户理解目标和差异之后发生；保留运行取消、错误恢复、dirty/pending及原子采纳规则。不把生成成功误称为已经记住。

## 动线3：找回并管理我发出的成果

**用户故事**：同事再次索要文件，或某个成果不应继续公开时，我要先确认是哪一份，再复制或撤销链接。

**主路径**：认出成果 → 打开已分享内容核对 → 复制链接；或确认影响 → 撤销 → 从列表消失并确认链接失效。

分享行的信息层级：

1. 文件名作为可识别主信息；完整路径保留为次信息/可展开信息，避免长路径压过名字。
2. 来源会话标题与分享时间用于辨认上下文；来源链接仍带原agent/conversation。
3. 显式“查看分享”“复制链接”，撤销作为次要危险动作，与复制拉开层级。
4. 撤销确认明确“此链接将立即失效”，失败必须在当前确认弹层中可见，不能只在被遮挡的页顶报错。

“查看分享”可复用已有公开分享页，不新增私有文件预览系统。只列未撤销不等于文件仍然存在，不能标“正常可访问”或展示未经统计的访问量、到期时间。

**空态**：去工作区完成工作并从成果版本发起分享；不在本页增设缺乏来源版本的“新建分享”。

## 动线4：找到异常并回到工作

**用户故事**：我记得某次工作失败或消耗较多，希望找到对应事项、理解状态，并进入能继续处理的地方。

**主路径**：选择时间范围 → 识别异常/筛选 → 找到对应专家和时间的工作 → 明确进入对话/提案/运行详情 → 继续处理。

信息层级：

1. 时间范围与简明本人汇总，成本明确“已记录”及覆盖情况；不展示推算账单、余额或额度。
2. 运行明细与状态筛选作为主要工作区。可加“失败”快捷，复用已有status URL过滤，不混入超时/取消而不说明。
3. 行主信息为专家、来源、状态、时间；耗时/成本/Token帮助判断；运行ID降为次信息或详情数据。
4. 显式显示落点动作“回到对话”“审核提案”“查看运行”，取决于现有runDestination和权限，不再让用户猜整行点击去哪里。
5. 明细筛选与汇总窗口作用域清楚，筛选失败时不把上面的全窗口汇总误写成失败子集统计。

现有数据没有运行任务名称或会话标题，不能凭空添加“工作名称”；若后续确认需要该能力，单独扩展真实投影。无run权限时只展示有权汇总；无overview权限时保留完整明细任务。

## 动线5：确认登录并处置风险

**用户故事**：我想检查其他地方是否还登录着，识别需要退出的会话，并在必要时更换密码。

**主路径**：确认当前会话 → 查看其他会话及最近活动 → 撤销一条 → 原地看到结果。

**改密路径**：选择修改密码 → 填写当前/新/确认 → 明确全部会话将撤销 → 提交 → 到登录页重新登录。

信息层级：

1. 当前会话单独标明，作为比对锚点；不提供撤销当前会话。
2. 其他会话以最近活动时间、IP、完整UA辅助判断，撤销动作就近出现。不能根据现有字段猜地理位置、设备名称或风险等级。
3. “修改密码”作为独立清晰的任务入口，按需展开表单，不让三行空密码占据默认主要空间。
4. 鲜度不足只在会话管理区解释原因并提供重新登录，不能自动登出或把整页误报失败。
5. 撤销失败在确认弹层中可见并保留重试，成功关闭弹层并更新列表。

用户进入时不一定是检查异常；修改密码入口必须立即可发现，不能藏进不明“更多”。没有准确设备解析时保持事实信息，不用UI包装制造虚假识别能力。

## 动线6：改姓名并确认当前身份

**用户故事**：我希望专家和平台使用正确姓名，同时能确认自己登录的是哪个账号。

**主路径**：查看当前姓名与用户名 → 编辑姓名 → 保存 → 原地确认及侧栏同步。

信息层级：姓名和用户名先出现；角色用于确认身份，业务ID放在按需查看的账号详情，仍可完整读取。只有姓名可改，不用禁用输入框暗示用户名或角色有编辑路径。资料页无需头像上传、邮箱等未支持字段，也无需大面积身份卡或统计。

## 端到端验收目标

- 进入任一目的地，用户能辨认当前任务、主要动作和完成去向。
- 记忆编辑/提案采纳有明确区别，不把已生成当已写入，不把个人目标和专家共享目标混淆。
- 提案审阅先看到完整影响，再查看依据并作决定，前后正文、索引与证据不被截断。
- 复制/撤销前能够核对具体成果；失败在当前任务上下文可见。
- 使用记录的落点可预见，且筛选、成本覆盖和权限口径不失真。
- 安全会话判断基于真实字段，改密后果在提交前明确。
- 现有权限、草稿保护、pending、冲突、回滚、分页及键盘焦点不回退。
