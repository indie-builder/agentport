## 1. 当前有效决定

**2026-10-25 用户最新范围校准（优先于本文旧的“复刻”措辞与上轮对照优先级）：**建设 PACE 内置知识库，流程是管理知识/同步资料→绑定指定专家→专家检索、使用并引用→持续更新与删除。WeKnora 是能力与处理逻辑的参考，不以完整复制其独立产品为验收目标。认证、专家、聊天、执行、模型、队列与审计复用 PACE；外部平台授权接入、独立客户端、多租户等不纳入本轮。官方文件定义与可导出规则仍保留，但不据此扩建对外知识服务。

用户补充：外部同步包括 **GitHub、GitLab、飞书**；平台自己的文件删除属于核心能力。**多模态直接参考 WeKnora 本身已有功能和实际处理链路，先查官方实现，再接入 PACE 现有管线，不重新自创一套或让用户重新定义模态范围。**不能未查证就把图片向量库、以图搜图或音视频扩为必做。GitHub 仓库文本文件来源已实现代码与本地 fixture，真实授权/限流/私有仓库未验收。此前确认的 Wiki/Feeds 目标继续保留，建设深度服务于专家使用。

PACE 内建设参考 WeKnora 的核心知识能力，继续使用现有 React/Fastify/Drizzle/Postgres/Redis/BullMQ 与 Claude Agent SDK。文档处理、检索引用、Wiki、Feeds及 GitHub/GitLab/飞书同步是一个整体目标，阶段只表达依赖与验收，不将同步和Wiki降为远期可选项。

企业知识主要在外部系统。基础设计从一开始就包含外部来源身份、层级、访问范围、版本、增量更新、删除与人工修改冲突；上传本地文档是入口之一，而非唯一模型。普通MCP在线查询与持续摄取同步是两种能力，不能相互替代。

**Feeds 暂按订阅源摄取理解**，对照参考源码的 RSS/Atom/JSON feeds；该含义尚未得到用户逐项确认。Feeds不是FAQ，也不自动包含自动日报、推荐、IM推送等新功能。FAQ保留为此前盘点的候选能力，与Feeds分开，本次表态不视为用户明确确认FAQ必做。

D-9已按最新决定更新为建设内置知识能力，状态明确为未实现；不再用旧“不做内置RAG”阻塞后续工作。图谱与图片语义检索仍是待单独选择的扩展，文档OCR及图片展示属于核心解析范围。

## 3. 完整能力范围

| 能力 | 用户可见内容 | 实施边界 |
|---|---|---|
| 知识库与文档管理 | 建库、文件夹、标签、搜索筛选、原件与来源 | 独立知识资源，复用现有资源页面和认证 |
| 多入口导入 | 批量文件/目录、网页、手写Markdown、外部来源、Feeds | 入口统一进入文档处理；保留原始链接、来源ID和层级 |
| 解析与OCR | PDF含扫描件、DOCX/PPTX/XLSX、MD/TXT/HTML/CSV等支持矩阵；表格、图片、页段定位 | 成熟解析服务，真实样本验证；不把DocReader单独当完整OCR |
| 异步处理 | 解析、切块、索引阶段可见；取消、错误、重试、重建 | 复用BullMQ/Redis，任务状态持久化，不伪装聊天run |
| 内容检查编辑 | 原件预览/下载、解析正文、分块编辑/启停、人工修改 | 重解析/外部更新覆盖人工修改的行为必须明确，避免静默丢失 |
| 混合检索与测试 | 中文关键词+向量、过滤、多库、可配置rerank、查看命中来源和顺序 | embedding与rerank独立配置，索引可重建，不承诺未测召回率 |
| 专家绑定 | 父子专家分别选择库，用只读search/read/list | 复用MCP及官方文件，补服务分派、run凭证与库范围校验 |
| 来源引用 | 标题、片段、页/段/表格或源系统链接；历史可回溯 | 解析→检索→消息保存→查看器完整贯通，模型不能自行授予权限 |
| 更新删除 | 替换、禁用、删除、重解析、模型切换重建 | 不再召回已删除/禁用旧文；来源变化驱动Wiki更新/失效提示 |
| Wiki | 自动主题页、索引与链接、引用、人工编辑、版本回退、更新状态 | 用现有Claude Agent SDK生成，通过受控工具保存，不引另一Agent循环 |
| Feeds | 订阅管理、定时摄取、新条目与内容更新、原文追溯、失败日志 | 暂按RSS/Atom/JSON feed；自然滚动消失不等于源文档删除 |
| FAQ（候选） | 标准问答、同义问法、导入编辑与检索测试 | 与Feeds分开，尚未单独确认必做，不擅自替换术语 |
| 飞书同步 | 企业知识资源选择、首次/增量/定时同步、错误与来源定位 | Wiki空间与云文档支持须分别核验，不能承诺所有飞书对象都可读 |
| GitHub同步 | 按仓库、分支/ref和目录范围同步资料，处理更新、重命名与删除 | 新增来源适配，复用现有摄取/任务/解析管线；Issues/PR/讨论区等按实际资料诉求决定，不由“GitHub同步”自动推导全部必做 |
| GitLab同步 | 项目/内容范围选择、实例配置、首次/增量/定时同步与删除处理 | 托管/自建实例，仓库/Wiki/Issue/MR内容类型须明确，不能用一个“已连接”覆盖 |
| 多模态（参考官方实现） | 以 WeKnora 已有图片/文档多模态功能和实际调用链为依据 | 先核官方解析、图片理解、索引、检索及回答使用方式，再复用 PACE 组件接入；不另创模态方案，不把未核实能力当作官方已有 |
| 导出与恢复 | 原件、配置、人工内容、Wiki/FAQ、绑定导出；索引重建 | 专家定义包与语料包分开，扩展现有备份清单 |

多模态源码核对见 [WeKnora 官方已有调用链](weknora-multimodal-reference.md)：独立图片/文档插图→VLM OCR和描述→文本索引；可选同空间图片向量；命中后按回答模型能力使用原图或描述并保留图片引用。当前 PACE 只有部分图片存取与 Docling OCR 接入，不能称已完成该链路。

静态依据：[入库](weknora-core-ingestion.md)、[检索/Wiki/同步](weknora-core-retrieval-wiki.md)、[PACE边界](weknora-core-pace-boundaries.md)。具体格式质量和源API完整性未实测。新企业来源细化见 [飞书/GitLab/Feeds范围](weknora-enterprise-sources.md)。

## 4. 外部来源从基础层进入

- 来源连接、授权范围、外部文档稳定ID、源URL、路径/层级与内容版本进入统一文档模型；重命名/移动不凭标题重复建文档。
- 首次抓取和增量游标、定时触发、可恢复错误和同步日志从一开始有明确契约；不为每个连接器重建整条解析索引管线。
- 远端删除、无访问权限、请求失败、用户缩小同步范围是不同状态，不能将一次列举失败当批量删除证据。
- 源文档与人工编辑/Wiki分清：同步不静默覆盖人工知识，冲突必须可见；变化沿文档→索引→Wiki来源依赖传播。
- 当前仍是单管理员项目，不扩多租户/RBAC；仅抓取配置凭证实际允许且用户选定的范围，不默认同步整个企业。导入共享库意味着向绑定专家开放，不宣称自动继承飞书/GitLab所有用户的ACL。
- 主动撤销来源或范围应立即限制新检索和原文访问；远端权限变化只能在后续同步/复核中发现，需显示最近检查时间。网络失败不能当删除，确认为失权的内容须退出可检索集合，相关Wiki摘录需失效或重建。历史聊天已保存摘录和已导出副本不会随索引删除自动收回，其保留规则须明确。
- 自建GitLab可能位于私网，需明确可信实例准入与worker可达性；不放宽所有输入URL的SSRF策略。

## 5. 官方文件与现有运行底座

智能体接入投影为官方 `.mcp.json`、技能 `SKILL.md` 及支持资源；不造 `.claude/knowledge`。大语料独立管理、按工具读取，小型静态资料/Wiki可选投影到技能references。工作区继续只读；知识内容写入通过平台入口或受控工具。

MCP协议、队列、认证、审计、专家、聊天、模型生成循环都复用。内置知识服务仍需实现run URL/凭证/授权、测试探针、定义导入导出；只加server记录不能闭环。引用须跨流式与历史保存，不能假定structuredContent已完整持久化。

## 6. 依赖与默认建议

- 复用现有Postgres/Drizzle、Redis/BullMQ；不为模仿Lite增加SQLite，也不重写为Go/asynq。
- 原件先用独立持久文件卷、备份覆盖；企业外部资料也可能需要本地解析副本，实际保留策略明确。
- 比较DocReader补OCR与完整解析服务如Docling，验证中文扫描页、表格、Office定位；允许容器是建议部署方式，用户尚未单独确认全离线或服务限制。
- 检索优先评估Postgres+成熟向量扩展，中文关键词在应用分词/扩展间做样本比较；不预设独立向量库或Neo4j。
- embedding/rerank/OCR服务独立配置；生成仍用Claude Agent SDK。接口、维度、费用、凭证和模型更换重建需验证。
- Feeds及企业连接器优先采用官方API和成熟依赖。不同来源的授权与内容覆盖按实际API确定，不凭品牌名称承诺全量支持。

## 7. 实施依赖与验收顺序

**A：基础契约与样本验证并行。** 定义来源/文档/引用/任务和专家绑定契约，同时验证解析、混合召回、飞书/GitLab读取及Feeds行为。连接器从本阶段参与，不等本地上传全做完再设计。

**B：基础闭环与首批接入并行建设。** 公共入库/任务/索引/引用/权限接口确定后，上传/检索/前端、飞书适配、GitLab适配、Feeds可并行。共享管线未就绪前可完成连接器凭证验证与资源列举，但不能声称端到端同步已完成。

**C：Wiki与持续更新贯通。** Wiki依赖稳定文档/来源/版本，可先并行开发编辑阅读与版本界面，再接现有SDK生成。来源更新/删除、同步日志、索引与Wiki刷新一起验收；Feeds作为持续输入一同验证。FAQ若纳入，再接同一检索与来源管线。

整体验收至少覆盖：外部选源→抓取/上传→解析/OCR→分块检查→搜索测试→专家带引用回答→源端更新删除→索引/Wiki变化→失败恢复→备份导出恢复；还包括权限不足、取消、重试、跨库未授权负例。飞书/GitLab不是只有入口或配置表单即完成。
