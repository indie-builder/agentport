# Agentport / PACE — 用户故事与功能契约

> 本文件是功能验收的唯一依据。每条用户故事都有明确的验收条件。
> 品牌：对外产品名为 **PACE**；仓库与包名保持 `agentport`。

---

## 角色

> 以下角色已于 2026-10-31 由 PR #129 合入 main（依据当前 main 的合并提交与代码）：默认角色是数据库初始数据，角色与功能授权均可配置，不按角色名硬编码。

| 角色 | 说明 |
|---|---|
| **平台管理员** | 全部功能与跨用户运维、审计；读取他人私有内容须留审计 |
| **用户** | 只使用被授权的专家；访问自己的私有会话、消息与个人记忆（与定义专家任务可由同一账户承担，但受授权范围约束） |
| **负责人** | 创建并管理本人负责的专家；分配使用、指定维护人员并转交 |
| **维护人员** | 只维护被指定的专家；不能新建、删除或转交专家 |
| **外部 Host** | 通过 `/mcp/:serverId` 连接平台的 MCP 端点（Claude Code、其他客户端）；使用该端点自己的 Bearer token，不因登录用户权限扩展 |
| **公开分享访问者** | 通过 `/s/<shareId>#<token>` 访问固定版本成果；只凭分享 token，不读管理会话 |

## EPIC 1 — MCP Server 管理

### US-1.1 登记一个 stdio MCP Server
**作为** 管理员，**我想** 填写命令、参数、环境变量并保存，**以便** 平台能启动它。

验收：
- 表单校验 `name` 为 `[a-z0-9-_]`、`command` 非空。
- 敏感 env 加密入库，列表与详情返回 `••••`。
- 保存后立即可在「测试连接」中使用。

### US-1.2 登记一个远程 MCP Server
**作为** 管理员，**我想** 填写 URL 与请求头，**以便** 复用已有的远程 MCP 服务。

验收：
- 仅允许 http/https；SSRF 校验（生产拒绝私网，开发放行 localhost）。
- headers 中的密钥脱敏返回。

### US-1.3 把一个 HTTP API 变成 MCP Server
**作为** 管理员，**我想** 填写 baseUrl 并定义若干工具（method、path、参数 schema），**以便** 不写代码就把内部 API 暴露给智能体。

验收：
- 支持 `GET/POST/PUT/PATCH/DELETE`，路径模板 `{param}` 自动替换。
- `paramsIn` 决定参数进 query 还是 body。
- 保存后平台生成 `/mcp/:serverId` 端点，带 Bearer token。
- 「测试连接」走平台端点，能看到工具列表。

### US-1.4 测试连接
**作为** 管理员，**我想** 一键验证配置，**以便** 在绑定给智能体前发现错误。

验收：
- 5 秒超时；失败返回可读错误，不抛 500。
- 成功展示 serverInfo、工具名与描述、耗时。
- 每次测试写入审计。

## EPIC 2 — 专家定义

### US-2.1 创建专家
**作为** 定义专家，**我想** 定义专家的名称、角色、职责与工作方式，**以便** 建立清晰的人格与行为边界。

验收：
- 创建表单前置名称、角色、职责与工作方式；角色来自 `AGENT_ROLES`；模型与 slug 收进「高级设置」。
- 职责与工作方式写在同一个「职责与工作方式」文本里，保存为专家 `systemPrompt` 并渲染到 `CLAUDE.md`；不新增职责字段，也不把 `description` 当职责用。`description` 只是一句话简介，创建表单不要求填写。
- slug 唯一，创建后不可改（目录名）；可留空自动生成，冲突保留草稿并提示。
- 保留导入专家包与 `agent.md`；专家网格常驻「新建专家」扇形动效卡与「创建数字分身」两张入口卡，均打开同一创建 Dialog，数字分身同时仍是角色选项。
- 创建后详情页有「开始对话」，链接直接选中该专家。
- model 可为任意模型 ID；提供常用建议值。

### US-2.2 绑定 MCP Server
**作为** 管理员，**我想** 选择若干 MCP Server，**以便** 智能体能使用它们的工具。

验收：
- 绑定关系存入数据库。
- 工作区 `.mcp.json` 包含全部绑定 server。
- 智能体的 `tools` 自动生成 `mcp__<server>__*`。

### US-2.3 绑定技能（Skills）
**作为** 管理员，**我想** 给智能体挂载「技能包」，**以便** 复用可复用的操作流程，而不用把它们塞进系统提示词。

验收：
- 技能是带 frontmatter 的 Markdown（`SKILL.md`），含 `name`、`description`。
- 可全局创建、可被多个智能体复用。
- 渲染到工作区 `.claude/skills/<slug>/SKILL.md`。
- 智能体 frontmatter 的 `skills` 字段列出已挂载技能。

### US-2.4 配置权限与运行时
**作为** 管理员，**我想** 控制智能体能做什么、花多少、跑多久。

验收：
- 可配置 `permissionMode`、`allowedTools`、`disallowedTools`。权限页面明确 SDK `allowedTools` 预批准与工具自身 `requiresApproval` 的服务端审批是两层约束；`default` 的宿主回调仅处理原生澄清提问，其余未预批准调用仍拒绝，不替代工具自身审批。
- `permissionMode` 支持 `default`（新建默认）、`plan`、`dontAsk` 与 `acceptEdits`，直接透传 Agent SDK；显式 `dontAsk` 拒绝原生交互提问，不进入回调。`auto` 依赖模型分类器，平台无法审计其决定，保存时返回 400。权限模式不会解除平台固定禁用的内置工具。
- 可配置 `maxTurns`、`maxBudgetUsd`、`timeoutMs`。
- 可配置 `effort`（可选）。
- 内置工具默认禁用；例外是容器内默认启用的 `Bash`（可通过 `disallowedTools` 显式拒绝）、主会话受路径规则约束的 `Read`/`Write`/`Edit`，以及按运行时配置单独启用的 `TodoWrite`。原生文件工具可访问专家记忆 Markdown（`agent-memory/`）与会话成果，`Read` 另可只读已挂载的附件、技能 references 与插件技能资源；子智能体的原生 `Read`/`Write`/`Edit` 默认启用，但只允许读写自身记忆 Markdown（`.claude/agent-memory/<slug>/`），兄弟、父级与未知子智能体拒绝，用户显式 deny 保留；`MEMORY.md` 由 SDK 原生按 project 自动加载，与主会话 auto-memory 相互独立，关闭文件工具不影响该自动加载。Bash 不经过原生文件工具的路径 hook，读写边界由 Docker 的只读/可写挂载约束。完整边界以 `docs/ARCHITECTURE.md` §3 与沙盒约定为准。
- 权限页的主会话与子智能体 `Read`/`Write`/`Edit` 分别默认显示「已启用（受路径限制）」与「默认启用（仅自身记忆）」；裸工具禁用规则优先。关闭只加裸禁用，恢复只移除该工具的裸禁用及裸允许项，不生成全局 allow、不清除已有路径规则。原「子智能体平台禁用且不可放行」文案已修正，UI 单测（web 72 条）与独立 UI 评审通过；关闭原生文件工具不代表关闭 Bash 的文件访问，也不关闭子智能体 `MEMORY.md` 自动加载。

### US-2.5 预览生成的文件
**作为** 管理员，**我想** 在保存前看到将要落盘的 `.mcp.json`、`CLAUDE.md`、agent md、skills，**以便** 确认配置正确。

验收：
- 文件预览与运行时实际生成内容一致。
- 支持复制。

### US-2.6 删除专家
**作为** 管理员，**我想** 删除不再需要的专家。

验收：二次确认；级联删除绑定关系与会话。

## EPIC 3 — 对话

### US-3.1 发起对话
**作为** 使用专家，**我想** 选一个专家并发送消息，**以便** 让它替我完成任务。

验收：
- 返回 202 与 `runId`、`conversationId`。
- 智能体不存在返回 404；停用返回 409 `AGENT_DISABLED`。
- 触发限流时返回 429。
- `/` 默认进入「找专家」`/agents`；专家卡主操作为「开始对话」并直接选中该专家，名称链接进入配置页。
- 停用专家卡片不提供可执行的「开始对话」；直接调用仍返回 409 `AGENT_DISABLED`。
- 专家卡不展示连接器/技能计数与 slug。
- 专家卡与两张创建入口卡统一 208px（`h-52`）高、同列宽、16px 网格 gap 与内边距；名称链接与角色分两行，介绍最多两行，完整资料在工牌中读取。
- 每张已有专家/分身卡提供「查看 <名称> 工牌」按钮，打开单个工牌 Dialog；工牌展示数字员工身份、姓名、角色、启停、完整介绍、员工编号（真实 id）与上岗时间（创建时间，使用真实 `createdAt`，含年与时区；缺失或无效显示「未记录」，空介绍显示「未填写介绍」）。工牌只读使用列表摘要，不请求专家详情、不展示提示词/绑定/成员资料；无创建或配置权限仍可查看已有工牌，停用专家工牌不提供可执行对话。
- 欢迎态无需打开会话历史即可看到当前专家并切换；搜索支持名称、角色和标识。
- 未发送草稿按会话保存在当前标签页，刷新恢复，切换会话不串稿；发送请求未接受前仍保留原稿，接受后不清除等待期间新写的草稿。

### US-3.2 流式输出
**作为** 使用专家，**我想** 实时看到文本与工具调用，**以便** 知道它在做什么。

验收：
- SSE 依次推送 `run_started`、`text_delta`、`tool_start`、`tool_input`、`tool_result`、`run_finished`。
- 订阅前的历史事件可回放（Redis Stream），不丢失。
- 客户端断开不泄漏 Redis 连接。

### US-3.3 对话历史
**作为** 使用专家，**我想** 看到历史消息并在同一会话中继续对话，**以便** 保持上下文。

验收：
- 会话列表按 agent 过滤，按最近更新排序。
- 打开会话加载全部消息（含工具调用）。
- 继续提问时模型能看到之前的上下文（SDK session 复用或历史注入）。
- 刷新页面后历史仍在。

### US-3.4 取消运行
**作为** 使用专家，**我想** 中途停止，**以便** 避免继续消耗。

验收：已终态幂等；运行中在数秒内停止本轮执行，后续无工具副作用；重复取消幂等。

### US-3.5 运行状态与成本
**作为** 管理员，**我想** 看到每次运行的状态、耗时、轮次、成本。

验收：`agent_runs` 全字段落库；运维·概况展示最近 6 条运行，概况、专家指标和趋势统一使用最近 7 个 UTC 自然日（含今天），趋势恰好 7 个日期点；完整运行列表在「运行」页查看。专家详情不再设运行统计页签，「查看运行」次级链接进入按该专家筛选的运行列表。

### US-3.6 会话操作菜单
**作为** 使用专家，**我想** 在当前会话的短标题旁打开更多菜单，管理会话而不先展开历史列表。

验收：
- 标题短显，完整名称可读取；菜单紧随标题。
- 重命名更新当前标题与列表，Fork 复制已有消息到独立会话。
- 删除必须明确确认；删除当前会话、消息和已结束运行记录，已有 Fork 保留。
- queued/running 会话返回 409，删除失败保留原会话和未发送输入。
- 尚未保存的新会话不提供可执行的操作；删除中禁止重复提交、继续发送或离开。

## EPIC 4 — 平台与运维

### US-4.1 登录
**作为** 平台用户，**我想** 用账号密码登录，**以便** 保护配置与私有数据。

验收：Better Auth 账号密码登录，会话写 PostgreSQL 并以 httpOnly、SameSite=Lax 的 `agentport_token` Cookie 保存（不使用 JWT，也不在 Redis 校验会话）；密码哈希与校验由 better-auth 管理；错误不区分用户名/密码；登录限流；主按钮文案为「登录」/「正在登录…」/「重试」，登录成功回到工作区（`/` 按账户权限落到第一个可用入口，无业务权限时进入个人资料）。管理员引导只在首次初始化创建管理员、不覆盖已有密码（已合入 main，PR #129）。

### US-4.2 运维·概况
**作为** 管理员，**我想** 从独立的运维入口一眼看到规模与最近运行。

验收：从底部「运维」进入独立导航，再进入「概况」（原 `OverviewPage`）；业务导航不出现运行、运行环境、健康与审计。运行次数、运行成本、专家、连接器四项概况；连接器数量与资源中心可管理列表一致，不包含平台内部知识连接。最近 6 条运行与完整运行列表入口；审批与失败运行统一进入「需要处理」，健康异常单独链接诊断页。专家名称直接链接对应配置页；趋势提供数值刻度和可展开的同源数据表。运维导航提供「返回工作区」。

### US-4.3 审计
**作为** 管理员，**我想** 追溯关键操作。

验收：配置变更、连接测试、对话请求/取消、运行起止都有记录；只存摘要。

### US-4.4 健康检查
验收：`/health/live` 与 `/health/ready`（DB + Redis）。

### US-4.5 部署
**作为** 管理员，**我想** 用一条命令在本机或服务器跑起来。

验收：`pnpm run up` 一条命令完成依赖启动、沙盒镜像构建、迁移、api/worker 启动与冒烟，结束后 api/worker/web 可用；迁移由 compose 的 `migrate` 服务在 api 启动前自动执行（直接操作宿主机时仍可手动 `pnpm db:migrate`）。

## EPIC 5 — 插件内容查看

### US-5.1 查看插件详情与真实文件

作为管理员，我可以从插件名称进入详情，查看插件包含的具体能力及正文，再决定是否绑定到专家。

验收条件：

- 插件名称进入独立详情页，编辑、安装、导入导出和删除功能保持可用；详情本身只读。
- 身份头下用页内「简介 / 内容」两个 Tabs 切换，全部抽屉、Sheet 与弹层移除；页面恰好一个主标题。
- 简介页签只展示根 README，不展示能力索引、来源或能力入口；无 README 时给简洁空态并指向内容页签，不编写介绍或拿首个技能冒充说明。
- 内容页签在页内展示完整真实目录树与当前正文；桌面左右可拖动分栏，窄屏目录在同一页内可折叠。目录树用真实文件/目录名，目录优先、可折叠，只有当前文件铺选中底色，技能目录内 `SKILL.md` 优先；manifest、hooks、MCP、支持文件与空文件全部可达，不以数量替代内容。默认文件为 README → 技能 `SKILL.md` → 首个真实文件。
- 桌面阅读区补 24px 内边距，路径工具栏与模式切换同一行，工具栏到正文 16px；窄屏按现有间距 token 收紧，分隔线与正文不再 0px 贴合。
- 点击 README 或正文内真实文件链接切到内容页签并定位对应文件；显式选择文件回到阅读模式。
- 页签使用原生关联与键盘导航；非活动面板不可聚焦但保持挂载，切回时保留各自阅读滚动位置；键盘可以选择文件、阅读长内容。
- 正文显示实际路径 breadcrumb 与 frontmatter 语义名称（缺失时用路径名）；Markdown 默认阅读并可切源码，其余文件直接显示源码和行号，原文随时可看。
- 页签、选中文件与模式进入 URL（`tab=intro|content`、`file`、`mode=read|source`），默认简介且无文件；刷新和浏览器前后退可恢复，切到简介保留选择，回到内容恢复；不存在的文件给出说明并回退。
- 加载、请求失败、404、无文件和空文件均有明确状态，错误可重试或返回列表。
- Markdown/脚本只读展示，不执行、不作为 HTML 注入；只有插件内真实存在的相对文件链接可点击。
- 内容区按真实文件路径展示，不另建能力索引；多来源文件在目录树中各自可达。

## EPIC 6 — 端到端智能体使用故事（待逐条核对）

> 本组只描述用户使用智能体完成真实工作的完整链路，用来逐条核对验收；**不代表当前已完整支持，也不把全部条件预先列为确定缺口**。已由 US-1～US-5 覆盖的细节直接引用，不在此重复。核对范围只含智能体自身行为；云盘、项目空间、多端协同、分享发布等云服务概念不在内。
>
> 首轮原生 TodoWrite 只是 US-6.3 多步骤链路中的一段；产出查看是 US-6.1 的下一步，不能以清单进度替代成果验收。

### US-6.1 资料分析交付并修改
**目标**：把资料交给智能体，得到可用于决策的分析或报告，并能就地要求修改直到可用。

**上下文**：智能体已通过知识库连接（只读检索，见 `docs/ARCHITECTURE.md` §4 内置知识 MCP）或 MCP 工具取得资料；也可以随本轮消息上传临时附件（文本/图片/PDF，只读挂载并由原生 `Read` 读取，见 §3.4）；同一会话已有历史与已读结论。

**执行与确认**：检索→分析→交付；资料不足或范围不清时先问（见 US-6.2），不编造；用户在同一会话提出修改，模型沿用上文与已读资料继续（US-3.3）。

- 删除认证资料后以同一 `businessId` 重建账户，原业务归属、角色、成员授权和个人记忆恢复。
- 重建历史身份必须显式确认「恢复原身份和授权」，不能用新建流程静默接管；未确认时拒绝（409），界面先展示将恢复的原授权。
- 旧会话不复活：重建前签发的 Cookie 失效，访问受保护入口返回 401，不复用旧 session 行。
- 业务记录不因认证账户删除而级联丢失；数据库迁移与隔离测试覆盖上述关联。

### US-8.2 首次初始化（bootstrap）与管理员保护
**作为** 平台管理员，**我想** 只在首次初始化时创建管理员，**以便** 后续启动或登录不会覆盖我改过的密码。

验收：
- 首次初始化创建管理员；重复启动、重复登录都不覆盖已有密码。
- 管理员密码只能通过显式账户操作修改，不能靠重启或改启动配置被动重置；已初始化后清理普通账户或认证资料不会重播环境密码。
- 账户可停用；停用撤销全部会话，重新启用不恢复旧 Cookie。
- 不能删除、停用或降权最后一名活跃管理员；该操作返回 409，矩阵整体保存与账户变更在同一事务内校验。
- 状态：已由 PR #129 合入 main。

### US-8.3 平台管理员
**作为** 平台管理员，**我想** 管理全部功能并跨用户运维，**以便** 平台可运营、可审计。

验收：
- 拥有功能树全部动作，可跨用户查看运维数据与审计记录；读取他人私有内容须留审计（目标 businessId、对象 ID、动作、requestId，不写正文或密码），不只靠前端隐藏。
- 不因管理员身份改变独立 MCP token 与公开分享 token 的校验规则。

### US-8.4 用户使用授权专家
**作为** 用户，**我想** 只看到并使用被授权的专家，**以便** 在职责范围内完成工作。

验收：
- 专家列表、直接 URL、对话、运行与成果入口都只允许已授权专家；未授权请求被服务端拒绝，不是只隐藏菜单。
- 用户只能访问自己的私有会话、消息、运行与个人记忆；其他用户不能读取。
- 用户不能管理账户、全局资源或其他用户的数据。

### US-8.5 负责人管理本人专家
**作为** 负责人，**我想** 创建并管理本人负责的专家、分配使用与维护并转交，**以便** 把专家交给合适的人使用和维护。

验收：
- 可创建并管理本人负责的专家；可分配使用、指定维护人员、转交专家。
- 转交后原负责人不再拥有该专家管理权，新负责人获得管理权；授权变化即时生效。
- 不能管理账户、全局资源或其他角色授权；不能读取其他用户正文。
- 多角色叠加只合并完整授权，不把某角色的动作与另一角色的对象范围拼成更大权限。

### US-8.6 维护人员维护指定专家
**作为** 维护人员，**我想** 只维护被指定的专家，**以便** 在不扩大权限的前提下保持专家可用。

验收：
- 只能维护被指定的专家；未指定专家在列表、直接 URL 与服务端都被拒绝。
- 不能管理账户、全局资源或授权，不能新建、删除或转交专家。
- 不因维护关系获得其他用户会话、消息或个人记忆的读取权。

### US-8.7 角色·功能矩阵
**作为** 平台管理员，**我想** 在角色×功能勾选矩阵中配置授权，**以便** 调整职责而不改代码。

验收：
- 顶部横向每个角色一列，左侧纵向为功能层级树；父功能下缩进显示查看、创建等子功能并可整组展开收起，不平铺为「专家 · 查看」。列头与功能行头视觉区分，中间单元格只放勾选状态，父级按叶权限三态显示；授权范围在矩阵外的角色设置中配置，整张矩阵一次保存。
- 角色与功能授权存 DB、可配置；新增/调整角色不需要改代码，默认四角色只是初始数据，不按角色名硬编码。系统 admin 角色的授权固定、不可删除或改矩阵（可改显示名），其他默认与自定义角色可编辑。
- 评估与定时任务在功能树中分立，不共用一条权限开关。
- 服务端每个业务入口声明并执行动作授权与对象范围检查；前端菜单与动作由同一功能目录驱动，隐藏不等于授权。
- 多角色只合并完整授权结果；矩阵变更后的新授权/撤权即时生效，并有审计。

### US-8.8 对象范围与跨用户隔离
**作为** 平台管理员，**我想** 让同一授权同时受动作与对象范围约束，**以便** 多角色不会串联出越权访问。

验收：
- 每条授权同时包含动作与对象范围（全部/本人/被指定）；判定必须同时满足两者。
- 用户、负责人、维护人员的对象范围分别落到本人、本人负责专家、被指定专家；不能通过另一个角色把范围扩大到其他用户。
- 平台管理员可跨用户运维与审计；负责人与维护人员不因角色获得其他用户正文读取权。
- worker 与 API 使用同一授权结果；worker 不以默认管理员身份绕过范围检查。
- 所有入口（含运行、成果、附件、记忆、评估、定时任务、审计）都有 access 声明，缺失声明按拒绝处理。

### US-8.9 私有会话、消息、运行与个人记忆
**作为** 用户，**我想** 让我的会话、消息、运行和个人记忆彼此隔离，**以便** 其他人不因角色看到我的正文。

验收：
- 私有会话、用户消息、运行与个人记忆按 `businessId` 归属；跨用户读取在服务端拒绝。
- 个人记忆按 `businessId` 独立目录与锁隔离；删除或重建认证账户后，同 `businessId` 可恢复。
- 既有专家共享 auto-memory 的读写语义保持不变；个人记忆与专家记忆不互相替代，也不借隔离改动把专家记忆改成只读或私有。
- 平台管理员跨用户运维与审计有记录；负责人、维护人员不因管理专家而读取他人正文。

### US-8.10 评估与定时任务分立
**作为** 平台管理员，**我想** 让评估与定时任务使用独立授权，**以便** 一类权限不会隐含另一类权限。

验收：
- 功能树中评估与定时任务是两个独立分支，可分别授予角色。
- 只有评估授权不能创建、运行或修改定时任务；反之亦然。
- 两者各自的运行/结果入口同样执行动作与对象范围检查。

### US-8.11 独立 MCP 与公开分享凭据边界
**作为** 平台管理员，**我想** 让 MCP 与分享凭据保持独立，**以便** 登录用户权限不会意外扩大外部访问。

验收：
- `/mcp` 平台端点继续只校验 `PLATFORM_MCP_TOKEN`；`/mcp/:serverId` 继续只校验该 server 的 Bearer token。
- 公开分享继续只凭 `/s/<shareId>#<token>` 访问；这些凭据不因登录用户、角色或管理员权限而放宽。
- 用户权限不覆盖上述凭据；凭据失效、撤销或来源删除仍按既有 401/404 语义处理，不泄露存在性。

### US-8.12 范围外与验收状态
**作为** 项目负责人，**我想** 明确本期不做什么，**以便** 账户/RBAC 不扩成企业身份平台。

验收：
- 本期不做第三方登录、飞书/钉钉等身份源同步、套餐额度/计费、组织多租户、权限 DSL 或空适配框架；本人运行用量与已记录成本展示见 US-10.6。

### US-10.2 个人记忆

**作为** 已认证用户，**我想** 在个人模块维护个人记忆，**以便** 所有专家默认了解我的长期信息与协作偏好而无需复述。

**作为** 已认证用户，**我想** 在个人模块发起并审核历史回顾，**以便** 把可复用结论采纳到个人记忆、专家记忆或规则。

### US-10.4 安全与会话

**作为** 已认证用户，**我想** 在个人模块改密并管理自己的登录会话，**以便** 撤销不再使用的会话并保护账号。

### US-10.5 我的分享（跨会话）

### US-11.18 额外来源与外部能力（待依赖）
**作为** 管理员，**我想** 接入更多来源并了解未授权能力，**以便** 按依赖推进而不是被虚报完成误导。

验收：
- 来源连接类型共 14 种：原有 GitHub、GitLab、飞书 wiki/drive、RSS/Atom/JSON Feed 五种保留；Lark wiki/drive、Notion、Confluence、语雀、钉钉、IMA、Seafile、Nextcloud 九种已落 shared/API/DB/worker/Web 本地链路与逐类 fixture，真实账号、配额与私有部署仍待验收（K-X3）。
- 九种新增来源各有最小配置与范围：Lark 用 App ID/Secret 与空间/节点/目录 Token；Notion 用 Integration Token 与 page/database/data_source UUID；Confluence 支持 Cloud Basic、Cloud scoped、DC PAT 三种认证；语雀用 Token 与数字 repo ID；钉钉用 Client ID/Secret 与 operator Union ID；IMA 只同步指定知识库；Seafile 按 11+ Bearer、库 UUID 与库内相对目录；Nextcloud 用站点/用户名/App Password 与目录路径。连接身份字段创建后不可修改，换站点/账号必须新建来源。
- 身份与内容边界随供应商事实：Seafile 文件身份为 repo UUID + 规范化路径的 SHA-256，改名表现为新增/旧不可见；Nextcloud 用全局 `oc:id` 而非路径或 `oc:fileid`；Notion 原生 Markdown 的 `truncated`/`unknown_block_ids` 任一不完整即该页失败；钉钉在线文档必须经 node URL 解析 `docKey`，缺 docKey 明确失败；IMA 对成功但无原文 URL 的媒体报 `content_unavailable`，笔记仅作者可读且只提供纯文本。
- 每个来源每轮重新枚举并读取完整快照，内容哈希相同不建新版本、不重算向量；这是“全量读取、内容增量入库”，不是远端 changed-only 或断点续传。只有完整枚举且本轮无失败时才可按 `syncDeletions` 停用不可见条目；根 404/403 不是空根，任何分页/单项失败都不推导删除。
- 真实私有仓库、企业权限、分页与限流仍需账户与可测试范围，标真实服务待验收；GraphRAG 需要 Neo4j 与抽取模型费用，未授权新增服务，标待依赖。音频 ASR 另见 US-11.19。
- 状态：目标验收，进行中，实际结果与依赖见 [任务记录](tasks/knowledge-weknora.md)（K-V2/X2/X3）。

### US-11.19 音频转录与时间引用
**作为** 管理员与使用专家，**我想** 上传音频后得到可检索的转录与真实时码引用，**以便** 从会议或录音中定位原话。

验收：
- 知识库可绑定启用的 ASR profile：类型固定为 OpenAI 转录（段级时间），字段为名称、完整最终 Endpoint URL、模型 ID、可选 API Key 与启用状态；不新增供应商选择、转码器、独立服务或环境变量。模型测试入口返回 409 且不联网、不计费，验证只能通过显式音频上传。
- 仅接受 mp3/wav/m4a/flac/ogg 五种且按真实字节与声明/后缀一致；单文件上限 25,000,000 字节；空文件、超限、伪装格式在写 blob/文档/任务前被拒绝。
- 转录使用唯一 multipart `verbose_json` + 段级 `timestamp_granularities[]=segment` 协议，完整 Endpoint URL 不自动补 `/v1`，Bearer 仅在配置密钥时发送；段级 start/end 转真实毫秒，正文与块时码来自真实 segment，不按总时长均摊或按字数插值。
- 有段级时码时，文档详情、检索命中与引用显示真实时间范围（如 `00:01.250–00:03.500`），并可下载音频原件与转录文本；没有 segments 时仍可索引/读取顶层文本，但详情明确显示「无时码」，不作为时码验收通过，也不编造时间。
- 取消/超时沿既有队列不切版；`chunksOnly` 只补向量、不重新转录；关闭或切换 ASR 只影响后续摄取，历史音频版本、原件与既有引用仍可读；ZIP 只带 profile 名称与 model，不含 endpoint/key，导回不重新转录。
- 真实端点可用性、时间戳覆盖、长音频时延、转录质量与费用尚未验收；自动/手动重试可能重复计费，不声称 exactly-once。
- 状态：目标验收，进行中，实际结果见 [任务记录](tasks/knowledge-weknora.md)（K-X1）。

## 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 密钥加密、SSRF 防护、容器隔离、日志脱敏、限流 |
| 可观测 | 结构化日志 + runId 关联 + 审计表 |

| 可访问性 | 键盘可达；对比度 ≥ WCAG AA；焦点可见 |
| 可测试 | 每条用户故事至少一个自动化测试或明确的手工验收步骤 |
