# Agentport / PACE — 用户故事与功能契约

> 本文件是功能验收的唯一依据。每条用户故事都有明确的验收条件。
> 品牌：对外产品名为 **PACE**；仓库与包名保持 `agentport`。

---

## 角色

> 当前仍是单账号，不新增权限角色。下表区分同一账号承担的业务任务与外部访问身份。

| 角色 | 说明 |
|---|---|
| **使用专家** | 在「找专家」发现并选择专家、开始对话、取回交付物（与定义专家同一账号） |
| **定义专家** | 创建和配置专家、维护专家记忆（自动进化是另一项已确认缺口，与使用专家同一账号） |
| **管理员** | 唯一登录账号，承担以上两类业务任务与运维 |
| **外部 Host** | 通过 `/mcp/:serverId` 连接平台的 MCP 端点（Claude Code、其他客户端） |

## EPIC 1 — MCP Server 管理

### US-1.1 登记一个 stdio MCP Server
**作为** 管理员，**我想** 填写命令、参数、环境变量并保存，**以便** 平台能启动它。

验收：
- 表单校验 `name` 为 `[a-z0-9-_]`、`command` 非空。
- 敏感 env 加密入库，列表与详情返回 `••••`。
- 保存后立即可在「测试连接」中使用。

### US-1.2 登记一个远程 MCP Server
**作为** 管理员，**我想** 填写 URL 与请求头，**以便** 复用已有的远程 MCP 服务。

验收：
- 仅允许 http/https；SSRF 校验（生产拒绝私网，开发放行 localhost）。
- headers 中的密钥脱敏返回。

### US-1.3 把一个 HTTP API 变成 MCP Server
**作为** 管理员，**我想** 填写 baseUrl 并定义若干工具（method、path、参数 schema），**以便** 不写代码就把内部 API 暴露给智能体。

验收：
- 支持 `GET/POST/PUT/PATCH/DELETE`，路径模板 `{param}` 自动替换。
- `paramsIn` 决定参数进 query 还是 body。
- 保存后平台生成 `/mcp/:serverId` 端点，带 Bearer token。
- 「测试连接」走平台端点，能看到工具列表。

### US-1.4 测试连接
**作为** 管理员，**我想** 一键验证配置，**以便** 在绑定给智能体前发现错误。

验收：
- 5 秒超时；失败返回可读错误，不抛 500。
- 成功展示 serverInfo、工具名与描述、耗时。
- 每次测试写入审计。

## EPIC 2 — 专家定义

### US-2.1 创建专家
**作为** 定义专家，**我想** 定义专家的名称、角色、职责与工作方式，**以便** 建立清晰的人格与行为边界。

验收：
- 创建表单前置名称、角色、职责与工作方式；角色来自 `AGENT_ROLES`；模型与 slug 收进「高级设置」。
- 职责与工作方式写在同一个「职责与工作方式」文本里，保存为专家 `systemPrompt` 并渲染到 `CLAUDE.md`；不新增职责字段，也不把 `description` 当职责用。`description` 只是一句话简介，创建表单不要求填写。
- slug 唯一，创建后不可改（目录名）；可留空自动生成，冲突保留草稿并提示。
- 保留导入专家包与 `agent.md`；数字分身只作为角色选项，不设独立创建卡。
- 创建后详情页有「开始对话」，链接直接选中该专家。
- model 可为任意模型 ID；提供常用建议值。

### US-2.2 绑定 MCP Server
**作为** 管理员，**我想** 选择若干 MCP Server，**以便** 智能体能使用它们的工具。

验收：
- 绑定关系存入数据库。
- 工作区 `.mcp.json` 包含全部绑定 server。
- 智能体的 `tools` 自动生成 `mcp__<server>__*`。

### US-2.3 绑定技能（Skills）
**作为** 管理员，**我想** 给智能体挂载「技能包」，**以便** 复用可复用的操作流程，而不用把它们塞进系统提示词。

验收：
- 技能是带 frontmatter 的 Markdown（`SKILL.md`），含 `name`、`description`。
- 可全局创建、可被多个智能体复用。
- 渲染到工作区 `.claude/skills/<slug>/SKILL.md`。
- 智能体 frontmatter 的 `skills` 字段列出已挂载技能。

### US-2.4 配置权限与运行时
**作为** 管理员，**我想** 控制智能体能做什么、花多少、跑多久。

验收：
- 可配置 `permissionMode`、`allowedTools`、`disallowedTools`。权限页面明确 SDK `allowedTools` 预批准与工具自身 `requiresApproval` 的服务端审批是两层约束；`default` 的宿主回调仅处理原生澄清提问，其余未预批准调用仍拒绝，不替代工具自身审批。
- `permissionMode` 支持 `default`（新建默认）、`plan`、`dontAsk` 与 `acceptEdits`，直接透传 Agent SDK；显式 `dontAsk` 拒绝原生交互提问，不进入回调。`auto` 依赖模型分类器，平台无法审计其决定，保存时返回 400。权限模式不会解除平台固定禁用的内置工具。
- 可配置 `maxTurns`、`maxBudgetUsd`、`timeoutMs`。
- 可配置 `effort`（可选）。
- 内置工具默认禁用；例外是容器内默认启用的 `Bash`（可通过 `disallowedTools` 显式拒绝）、主会话受路径规则约束的 `Read`/`Write`/`Edit`，以及按运行时配置单独启用的 `TodoWrite`。原生文件工具可访问专家记忆 Markdown（`agent-memory/`）与会话成果，`Read` 另可只读已挂载的附件、技能 references 与插件技能资源；子智能体的原生 `Read`/`Write`/`Edit` 默认启用，但只允许读写自身记忆 Markdown（`.claude/agent-memory/<slug>/`），兄弟、父级与未知子智能体拒绝，用户显式 deny 保留；`MEMORY.md` 由 SDK 原生按 project 自动加载，与主会话 auto-memory 相互独立，关闭文件工具不影响该自动加载。Bash 不经过原生文件工具的路径 hook，读写边界由 Docker 的只读/可写挂载约束。完整边界以 `docs/ARCHITECTURE.md` §3 与沙盒约定为准。
- 权限页的主会话与子智能体 `Read`/`Write`/`Edit` 分别默认显示「已启用（受路径限制）」与「默认启用（仅自身记忆）」；裸工具禁用规则优先。关闭只加裸禁用，恢复只移除该工具的裸禁用及裸允许项，不生成全局 allow、不清除已有路径规则。原「子智能体平台禁用且不可放行」文案已修正，UI 单测（web 72 条）与独立 UI 评审通过；关闭原生文件工具不代表关闭 Bash 的文件访问，也不关闭子智能体 `MEMORY.md` 自动加载。

### US-2.5 预览生成的文件
**作为** 管理员，**我想** 在保存前看到将要落盘的 `.mcp.json`、`CLAUDE.md`、agent md、skills，**以便** 确认配置正确。

验收：
- 文件预览与运行时实际生成内容一致。
- 支持复制。

### US-2.6 删除专家
**作为** 管理员，**我想** 删除不再需要的专家。

验收：二次确认；级联删除绑定关系与会话。

## EPIC 3 — 对话

### US-3.1 发起对话
**作为** 使用专家，**我想** 选一个专家并发送消息，**以便** 让它替我完成任务。

验收：
- 返回 202 与 `runId`、`conversationId`。
- 智能体不存在返回 404；停用返回 409 `AGENT_DISABLED`。
- 触发限流时返回 429。
- `/` 默认进入「找专家」`/agents`；专家卡主操作为「开始对话」并直接选中该专家，名称链接进入配置页。
- 停用专家卡片不提供可执行的「开始对话」；直接调用仍返回 409 `AGENT_DISABLED`。
- 专家卡不展示连接器/技能计数与 slug。
- 欢迎态无需打开会话历史即可看到当前专家并切换；搜索支持名称、角色和标识。
- 未发送草稿按会话保存在当前标签页，刷新恢复，切换会话不串稿；发送请求未接受前仍保留原稿，接受后不清除等待期间新写的草稿。

### US-3.2 流式输出
**作为** 使用专家，**我想** 实时看到文本与工具调用，**以便** 知道它在做什么。

验收：
- SSE 依次推送 `run_started`、`text_delta`、`tool_start`、`tool_input`、`tool_result`、`run_finished`。
- 订阅前的历史事件可回放（Redis Stream），不丢失。
- 客户端断开不泄漏 Redis 连接。

### US-3.3 对话历史
**作为** 使用专家，**我想** 看到历史消息并在同一会话中继续对话，**以便** 保持上下文。

验收：
- 会话列表按 agent 过滤，按最近更新排序。
- 打开会话加载全部消息（含工具调用）。
- 继续提问时模型能看到之前的上下文（SDK session 复用或历史注入）。
- 刷新页面后历史仍在。

### US-3.4 取消运行
**作为** 使用专家，**我想** 中途停止，**以便** 避免继续消耗。

验收：已终态幂等；运行中在数秒内停止本轮执行，后续无工具副作用；重复取消幂等。

### US-3.5 运行状态与成本
**作为** 管理员，**我想** 看到每次运行的状态、耗时、轮次、成本。

验收：`agent_runs` 全字段落库；运维·概况展示最近 6 条运行，概况、专家指标和趋势统一使用最近 7 个 UTC 自然日（含今天），趋势恰好 7 个日期点；完整运行列表在「运行」页查看。专家详情不再设运行统计页签，「查看运行」次级链接进入按该专家筛选的运行列表。

---

### US-3.6 会话操作菜单
**作为** 使用专家，**我想** 在当前会话的短标题旁打开更多菜单，管理会话而不先展开历史列表。

验收：
- 标题短显，完整名称可读取；菜单紧随标题。
- 重命名更新当前标题与列表，Fork 复制已有消息到独立会话。
- 删除必须明确确认；删除当前会话、消息和已结束运行记录，已有 Fork 保留。
- queued/running 会话返回 409，删除失败保留原会话和未发送输入。
- 尚未保存的新会话不提供可执行的操作；删除中禁止重复提交、继续发送或离开。

## EPIC 4 — 平台与运维

### US-4.1 登录
**作为** 管理员，**我想** 用账号密码登录，**以便** 保护配置。

验收：httpOnly cookie；scrypt 校验；错误不区分用户名/密码；登录限流；主按钮文案为「登录」/「正在登录…」/「重试」，登录成功回到工作区（`/` 重定向 `/agents`）。

### US-4.2 运维·概况
**作为** 管理员，**我想** 从独立的运维入口一眼看到规模与最近运行。

验收：从底部「运维」进入独立导航，再进入「概况」（原 `OverviewPage`）；业务导航不出现运行、运行环境、健康与审计。运行次数、运行成本、专家、连接器四项概况；连接器数量与资源中心可管理列表一致，不包含平台内部知识连接。最近 6 条运行与完整运行列表入口；审批与失败运行统一进入「需要处理」，健康异常单独链接诊断页。专家名称直接链接对应配置页；趋势提供数值刻度和可展开的同源数据表。运维导航提供「返回工作区」。

### US-4.3 审计
**作为** 管理员，**我想** 追溯关键操作。

验收：配置变更、连接测试、对话请求/取消、运行起止都有记录；只存摘要。

### US-4.4 健康检查
验收：`/health/live` 与 `/health/ready`（DB + Redis）。

### US-4.5 部署
**作为** 管理员，**我想** 用一条命令在本机或服务器跑起来。

验收：`pnpm run up` 一条命令完成依赖启动、沙盒镜像构建、迁移、api/worker 启动与冒烟，结束后 api/worker/web 可用；迁移由 compose 的 `migrate` 服务在 api 启动前自动执行（直接操作宿主机时仍可手动 `pnpm db:migrate`）。

## EPIC 5 — 插件内容查看

### US-5.1 查看插件详情与真实文件

作为管理员，我可以从插件名称进入详情，查看插件包含的具体能力及正文，再决定是否绑定到专家。

验收条件：

- 插件名称进入独立详情页，编辑、安装、导入导出和删除功能保持可用；详情本身只读。
- 身份头下用页内「简介 / 内容」两个 Tabs 切换，全部抽屉、Sheet 与弹层移除；页面恰好一个主标题。
- 简介页签只展示根 README，不展示能力索引、来源或能力入口；无 README 时给简洁空态并指向内容页签，不编写介绍或拿首个技能冒充说明。
- 内容页签在页内展示完整真实目录树与当前正文；桌面左右可拖动分栏，窄屏目录在同一页内可折叠。目录树用真实文件/目录名，目录优先、可折叠，只有当前文件铺选中底色，技能目录内 `SKILL.md` 优先；manifest、hooks、MCP、支持文件与空文件全部可达，不以数量替代内容。默认文件为 README → 技能 `SKILL.md` → 首个真实文件。
- 桌面阅读区补 24px 内边距，路径工具栏与模式切换同一行，工具栏到正文 16px；窄屏按现有间距 token 收紧，分隔线与正文不再 0px 贴合。
- 点击 README 或正文内真实文件链接切到内容页签并定位对应文件；显式选择文件回到阅读模式。
- 页签使用原生关联与键盘导航；非活动面板不可聚焦但保持挂载，切回时保留各自阅读滚动位置；键盘可以选择文件、阅读长内容。
- 正文显示实际路径 breadcrumb 与 frontmatter 语义名称（缺失时用路径名）；Markdown 默认阅读并可切源码，其余文件直接显示源码和行号，原文随时可看。
- 页签、选中文件与模式进入 URL（`tab=intro|content`、`file`、`mode=read|source`），默认简介且无文件；刷新和浏览器前后退可恢复，切到简介保留选择，回到内容恢复；不存在的文件给出说明并回退。
- 加载、请求失败、404、无文件和空文件均有明确状态，错误可重试或返回列表。
- Markdown/脚本只读展示，不执行、不作为 HTML 注入；只有插件内真实存在的相对文件链接可点击。
- 内容区按真实文件路径展示，不另建能力索引；多来源文件在目录树中各自可达。

## EPIC 6 — 端到端智能体使用故事（待逐条核对）

> 本组只描述用户使用智能体完成真实工作的完整链路，用来逐条核对验收；**不代表当前已完整支持，也不把全部条件预先列为确定缺口**。已由 US-1～US-5 覆盖的细节直接引用，不在此重复。核对范围只含智能体自身行为；云盘、项目空间、多端协同、分享发布等云服务概念不在内。
>
> 首轮原生 TodoWrite 只是 US-6.3 多步骤链路中的一段；产出查看是 US-6.1 的下一步，不能以清单进度替代成果验收。

### US-6.1 资料分析交付并修改
**目标**：把资料交给智能体，得到可用于决策的分析或报告，并能就地要求修改直到可用。

**上下文**：智能体已通过知识库连接（只读检索，见 `docs/ARCHITECTURE.md` §4 内置知识 MCP）或 MCP 工具取得资料；也可以随本轮消息上传临时附件（文本/图片/PDF，只读挂载并由原生 `Read` 读取，见 §3.4）；同一会话已有历史与已读结论。

**执行与确认**：检索→分析→交付；资料不足或范围不清时先问（见 US-6.2），不编造；用户在同一会话提出修改，模型沿用上文与已读资料继续（US-3.3）。

**产出与反馈**：交付物能在当前任务中找到并预览，必要时可下载；修改后看到新版本且上一版不被静默覆盖；刷新或重开历史仍可查看（US-3.3）。成果按版本挂在产生它的对话轮次与右侧成果面板；同一路径多版用单选版本菜单（最新 / 上一版 / 前 N 版 + 时间）切换，选中版本决定预览、下载、分享与「基于此版本修改」。图片成果仅 PNG/JPEG/GIF/WebP 在面板内预览，经鉴权下载且浏览器解码成功后才显示，损坏字节保留下载；PDF 成果经鉴权下载后用浏览器原生查看器预览（支持与 `%PDF-` header 门槛，损坏或加密时保留下载）；Office 等其余格式沿用既有行为，HTML/SVG 仅源码。固定版本公开分享见 US-7.1。

### US-6.2 需求不清时询问、关键操作前确认
**目标**：信息不足或操作有副作用时，智能体先问清楚或取得确认，而不是猜测执行。

**上下文**：智能体可见的规则/技能写明何时必须确认；MCP 工具可标记为需要批准。

**执行与确认**：澄清问题出现在对话流中且可回答，回答后继续同一任务；需要批准的工具调用显示待批准状态，批准后完成该次调用，拒绝则明确说明未执行；任何阶段都能停止（US-3.4）。

**产出与反馈**：待批准与已回答状态在对话和运行详情中一致可见（US-3.5）；副作用只在批准后发生，拒绝不产生。

**已验证与待核对验收**：原生 `AskUserQuestion` 已接通。SDK0.3.311真实探针确认 `default` 回调回答后继续、`dontAsk` 直接拒绝；隔离环境4次真实模型run通过：提问→刷新与运行详情均可回答→回答后同一run继续原生`Write`交付（列表/正文/下载哈希一致），`requiresApproval`工具在批准前副作用计数0、批准后1；拒答、等待中停止、整体超时均关闭问题并正确结束。公开问题以题序号/选项序号提交，服务端映射回原始SDK键值，对外统一脱敏。未覆盖：多问题/多选在真实模型下的组合、真实读屏与原生缩放；关闭原因在SDK取消路径记为通用`closed`。证据见 [任务记录](tasks/agent-clarification.md)。澄清提问只是US-6.2的一部分；当前仍没有通用的“任意工具调用挂起等待人工批准”宿主，MCP审批继续独立执行，不把本条视为整个故事全部完成。

### US-6.3 多步骤执行与子智能体协作
**目标**：较复杂任务被拆成可见步骤执行，必要时委派给子智能体，最后汇总成完整结果。

**上下文**：主智能体绑定子智能体（单层）及任务所需的技能、MCP 工具。

**执行与确认**：三步以上的任务用原生 `TodoWrite` 展示步骤（实现与边界见 `docs/ARCHITECTURE.md` §3.1）；委派通过 `Agent` 同步等待子智能体返回；子智能体受自身 `maxTurns` 与超时约束，不能再向下委派；越权工具与文件访问被拒绝。

**产出与反馈**：步骤清单只表示模型自报进度，不作为成功或成果质量判据；子智能体的清单不覆盖主清单；子智能体的最终结果纳入主会话答复并可查看。

**已验证与待核对验收**：当轮默认 `dontAsk` 下原生 `TodoWrite` 已在真实沙盒执行，4 次快照通过 SSE 与历史保存且浏览器刷新恢复；快照字节上限与导出可移植 env 已补行为测试。此证据仅覆盖进度环节；子智能体真实加载调用与最终汇总仍需独立验收。详细证据见 [任务记录](tasks/platform-capability-gaps.md)。

### US-6.4 专家记忆与规则跨会话复用
**目标**：在会话 A 中确立的偏好、结论或规则，在后续新会话中可直接复用，不必重复交代。

**上下文**：同一智能体的专家记忆目录（`agent-memory/`，跨 run 持久）与项目规则（`.claude/rules/`，随工作区渲染）。

**执行**：主会话可读写记忆 Markdown，新会话启动时加载；规则自动作用于每次运行。

**产出与反馈**：记忆的写入、编辑、删除在专家记忆面板可见；新会话在未复述的情况下遵循既有偏好或结论；记忆与规则冲突时行为可解释。UI 名称统一为「专家记忆」，不再叫「长期记忆」；专家记忆由原生 auto-memory 自动写入，不逐条确认。个人偏好与历史回顾见 US-7.2、US-7.3。

### US-6.5 失败或停止后恢复继续
**目标**：运行被用户停止、超时或基础设施中断后，用户知道发生了什么，并能从断点继续而不重复副作用。

**上下文**：同一会话的消息历史、SDK transcript 与运行记录（US-3.5）。

**执行与确认**：停止在数秒内生效：本轮执行结束且后续无工具副作用，重复取消幂等（US-3.4）；基础设施类失败由队列有限重试，业务失败不重试；用户下一条消息沿用会话上下文；已产生的消息、工具结果与清单保留。

**产出与反馈**：失败原因可读而非 500；继续后模型知道此前进行到哪一步；已完成的外部写操作不被重复执行，未完成项可明确接着做。

**待核对验收**：失败后同一会话续聊的上下文边界、部分产出是否保留、停止与重试的幂等，均未做真实运行验收。

### US-7.3 历史回顾
**作为** 使用专家或定义专家，**我想** 让模型从已有会话整理可复用的记忆提案，**以便** 我审核后决定是否写入。

验收：
- 「记忆 → 历史回顾」按专家筛选，可选择执行审核的专家、来源会话区间与补充要求；同一幂等键不会重复创建。
- 回顾是 `trigger='review'` 运行：不建沙盒、不追加消息、不写成果；无工具、无 `settingSources`、无持久会话，以结构化输出返回提案。
- 提案可写入个人偏好、专家 `MEMORY.md` 或专家规则；证据必须是来源消息原文的连续子串，否则审核失败。
- 采用、拒绝、回滚与手工编辑共用目标锁；采用后才写入目标并落 `memory_changes`，拒绝不改变内容。
- `MEMORY.md` 是索引，提案最多 200 行 / 25KB；详细内容写主题文件或规则。
- 回顾沿用专家预算、超时与取消；失败、超时、取消都有可读终态。
- 验收状态：后端、前端、权限与状态测试已通过；真实模型生成提案并采纳的完整链路尚未做浏览器验收（见 `docs/REMAINING-TODOS.md`）。
