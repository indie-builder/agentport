# PACE 设计规范（以 OpenUI Chat 为基准）

> 布局参考：https://www.openui.com/chat?form_factor=desktop。基础数值来自 2026-10-21 的 CDP 实测；品牌、主题色与对话页按 2026-10-24 的项目调整执行。

---

## 1. 整体结构

```
body #F5F5F5
├─ 侧栏（展开 272px / 收起 68px，透明底，在白壳之外）
└─ 外壳：下/右 4px 外边距，圆角 16px，表面 #FDFDFD，1px outline rgba(15,15,15,.06)
   └─ 主区
      ├─ 会话列表：对话标题 / 专家选择 / 搜索（可收起，与消息区同纸白底）
      ├─ 内容：最大宽 728px，水平居中，从顶部开始
      └─ 底部：多行输入区（最大宽 728px，圆角 16px）
```

**硬性规则**

1. **侧栏在白壳之外**：壳只占主区，下、右各留 4px，左侧紧贴侧栏。壳用 1px `outline var(--color-shell-line)`（`rgb(15 15 15 / 0.06)`），没有 border 与阴影。
2. 侧栏背景透明（与页面同色），不与主区分隔线——靠留白分开。
3. 对话历史默认隐藏，展开后头部直接显示带头像、可搜索的专家选择和新建动作，不显示重复的「对话」或「对话记录」标签。历史与消息区同用 `bg-surface`，外部主导航保持 `bg-canvas`。消息区左侧历史按钮使用虚线面板图标 `PanelLeftDashed`，右侧会话成果按钮使用镜像的 `PanelRightDashed`；桌面端（`lg` 起）同时显示「会话成果」文字，窄屏保留图标与无障碍名。两者均为常规 32px ghost 按钮，与导航品牌及折叠按钮共用同一水平中心线，但图形比导航的实线折叠图标更轻，避免两处视觉重复。欢迎态可显示当前专家选择器；已有消息的消息区显示短会话标题及紧随的更多菜单；历史隐藏时在消息区头部保留专家选择，历史展开时只在历史头部显示，避免重复入口。右侧会话成果与专家定义文件不同，不展示 `.claude` 配置树；仅展示服务端真实发布的成果，同路径可选择版本，提供静态阅读/源码与下载、基于此版本修改。无成果显示真实空态，不从回复猜测文件或伪造卡片。该链路已交付，运行验收证据见 `docs/tasks/agent-output-viewing.md`。窗口收窄时历史面板仍可收起；面板切换不得清空输入、变更专家或重建消息流。始终仅一个 h1。
4. 对话、空态、输入框共用同一条 728px 轴线（实测内容区 760px 含 16px 横内边距）。

## 2. 色彩

采用与 OpenUI Chat 一致的中性灰主题，不带暖色相：画布与外壳拉开两级亮度，文本为近黑中性色，状态色仍独立表达结果。

| 用途 | 值 | 角色 |
|---|---|---|
| 页面背景 | `#F5F5F5` | 中性灰画布，承托外壳与侧栏 |
| 外壳 / 卡片 / 登录页 | `#FDFDFD` | 工作表面，与画布相差约 3% 亮度 |
| 主文本 | `#171717` | 近黑中性色，保留清楚的正文层级 |
| 次要文本 | `#666666` | 中性灰，用于说明、占位符与辅助信息 |
| 弱文本 | `rgb(15 15 15 / 0.38)` | 仅装饰与禁用例外，不承载必读信息 |
| 悬停 / 弱底 | `rgb(15 15 15 / 0.045)` / `0.025` | 安静的交互层次 |
| 下沉底 / 选中底 | `#F0F0F0` / `#EBEBEB` | 中性灰层次；选中态使用深色文字 |
| 分隔线 / 强边线 | `rgb(15 15 15 / 0.09)` / `0.16` | 统一的中性透明边线 |
| 主按钮 / 发送 | `#171717` 实底，白字 | 主操作，白字对比度约 17.4:1 |
| 焦点 | `#8A8A8A` | 中性灰边框或单层外环，与表面约 3.2:1 |
| 状态 | 成功 `#187646` / 警告 `#8A5600` / 失败 `#B42318` | 仅小面积表达状态；状态区边框使用统一中性透明边线 |

主文本在表面色上约 17:1，次要文本约 5.7:1。所有控件仍使用 `primary`、`muted-foreground`、`ring`、`selected` 等语义令牌，不逐页写色值。代码块表面使用 `#F5F5F5`，注释与标点沿用可读的中性灰文字。字体、尺寸、布局与品牌素材不随本次主题调整改变。

|---|---|
| 外壳 / 线程容器 | **16px** |
| 对话输入区 | **16px** |
| 建议入口 | 沿用共享按钮圆角 |

## 4. 字体

- 字体：**Inter**（`Inter, "Inter Fallback", system-ui, sans-serif`）。等宽：**JetBrains Mono Variable / JetBrains Mono**，依次回退 `ui-monospace`、Geist Mono、`monospace`。
- **字号阶梯固定在 `styles.css` 的 `--text-*`，按语义唯一取值，不在页面里写硬编码字号。** 相邻档至少差 1px 或一个可见字重差：

  | Token | 尺寸 / 行高 | 唯一用途 |
  | --- | --- | --- |
  | `2xs` | 11 / 16 | 密集只读数据的次要行列：trace 时间戳、ID、分组小标签；**不用于可点击控件或正文** |
  | `xs` | 12 / 16 | 常规元信息：时间、ID、表格副信息；所有徽章 |
  | `sm` | 13 / 20 | 界面默认：导航、控件、表格单元格、说明 |
  | `base` | 14 / 22 | 列表与卡片标题 |
  | `md` | 15 / 26 | 阅读正文：对话、Markdown、气泡、运行步骤 |
  | `lg` | 16 / 24 | 页面标题（h1）与对话标题 |
  | `xl` | 18 / 26 | Markdown 一级标题 |
  | `3xl` | 24 / 32 | 欢迎标题、主统计数字 |

- `2xs` 只出现在高密度只读视图（运行 trace、连接器表格、版本历史）；同一类信息在常规页面上用 `xs`。判断标准是「这一屏是否需要在同样高度里塞下多列数值」，不是信息本身的性质。

- **Markdown 标题不小于正文**：H1 `xl` 18/600、H2 `lg` 16/600、H3–H6 `md` 15/600。正文只有一级（`md`），没有更多字号可用，所以 H3 以下靠 600 字重与间距区分，不再往下缩字号——小于正文的标题会比它概括的内容还弱。
- 阅读正文（`md`）使用 26px 行高；用户气泡与助手正文共用同一个行高，不再各自覆盖 `leading-*`。
- **对话欢迎区仅一行标题「今天想完成什么？」**：标题 `3xl`，500 字重，左侧配小幅木工插画。
- 对话输入框 15px；建议入口使用共享 sm outline 按钮，不另做大卡片。
- 侧栏条目 13px；分组标题 12px。
- 说明文字 13px，弱色。

> 对话欢迎区以一行问题、紧凑插画与输入区形成层次，不再堆叠两行同等字号的问候。

## 5. 图标

- **lucide**，`stroke-width: 1.75`，尺寸 **16px**（次级 14px，最小 12px）。
- 图标跟随文本色，不单独着色。
- 品牌：采用用户确认的 A 版艺术字组合——木工小狗双手搭在大写 `PACE` 上，像在亲手打造字标。字母为白底黑色轮廓，清理粗重黑块和装饰细节，嘴与舌头为黑白，工具保留少量木色、灰色和黄色，不添加红色装饰。完整 Logo 为 `public/brand/pace-wordmark.webp`（透明，768×568，约 51KB），登录页居中显示高 96px，展开侧栏显示高 32px；导航品牌区相应高 32px，与同排折叠按钮共用水平中心线，收起侧栏仍使用原 32px 木工矢量标记 `public/brand/pace-mark.svg`。本次完整艺术字是图片版，并非矢量路径；透明 PNG 母版与生成记录保存在 `docs/brand/`。人物头像、人物卡片动效、对话布局与现有 favicon 保持原样；界面配色统一遵循 §2。

登录页及展开侧栏的品牌 Logo 点击切换 `public/brand/scenarios/` 中下一张小狗图：采用用户选定的「轻推接力」：先解码图片，旧图向左轻退并淡出，新图同时从右侧淡入到位，全程 300ms、缓出曲线；96px 展示下位移为 8px，导航尺寸按比例缩小。两个图层叠放在同一固定占位中，不旋转、不弹跳。品牌区固定正方形占位，Logo 按钮使用 plain 透明变体，悬停和按压不添加底色；保留键盘焦点提示。点击不导航、不自动轮播，刷新恢复原 Logo；转场期间连点不重复触发。遵循系统减少动态效果设置，减少动态效果时直接换图。业务页面不插入这些图片。

## 6. 对话页（核心）

### 空态

```
会话列表（可收起）            消息内容（同纸白底）
对话             [+] [收起]   │
[头像] [选择专家 ▾]           │ [小幅木工小狗] 今天想完成什么？
[搜索对话]                   │
会话标题                     │ ┌────────────────────────────────┐
会话标题                     │ │ 描述你想完成的事…               │
                             │ │                                 │
                             │ │ Enter 发送 · Shift+Enter 换行 [↑]│
                             │ └────────────────────────────────┘
                             │ [梳理思路] [制定计划] [整理内容] [分析问题]
```

- 欢迎区、消息和输入区仍共用 728px 轴线，含水平内边距时最大 760px。主体纵向居中，左右沿输入区对齐，区块间距 24px；窗口收窄时自然换行与滚动。
- 木工 SVG（`public/brand/pace-chat-woodworker.svg`）宽 96px，保持原比例；嘴和舌头黑白，工具配色保留。仅空白对话欢迎态显示，开始对话后隐藏，不添加新动效。
- 输入区由 InputGroup + InputGroupTextarea + 底部 InputGroupAddon 组成，16px 圆角，一层中性边框，无叠加焦点光环。欢迎态文本区最小 80px，对话态最小 56px，均可随内容增高至 160px 后在文本区内部滚动。
- 发送按钮沿用共享黑底图标按钮（32px）；空输入仅禁用发送按钮，不能把仍可编辑的整组控件变淡。只有输入控件本身禁用时，InputGroup 才显示禁用背景和透明度。
- 快捷键提示放在输入区左下角，发送放右下角。运行详情链接保留在操作行。
- 四个短任务入口使用 sm outline 按钮，单行排列。点击只填写通用提示词并把焦点交还输入框，不自动发送，不宣称专家拥有未经配置的数据或工具能力。
- 不显示「绑定 server / 权限 / 最近运行」等元信息，不在建议按钮重复当前专家名称。

### 对话态

- 消息流最大宽 728px，居中。每一轮用户消息是一个独立浅灰胶囊（右对齐），助手回复紧随其后、按轮次成组；轮与轮之间只靠间距分开，不画横线——横线是重复信号，结构已经由胶囊、正文与读数行表达。空回复轮次显示「等待回复…」，不留空白。
- 运行读数（完成 · 轮次 · 耗时 · token · 成本 · 查看详情）是该轮的自然收尾：最新一轮常驻显示，更早的轮次常驻占位、默认透明，指到或键盘聚焦该轮时显影（`opacity` 150ms）；完整完成时刻放在 `title` 里。读数来自会话详情按 `run_id` 批量带回的指标，不逐条查。
- 运行中的状态沿用同一条读数行的位置与字号：脉冲圆点 +「等待回复／正在调用 X」+ 等宽计时，中断时追加重连。它跟在最后一轮回复下方，**不做成横跨整列的工具栏**；停止入口放在输入框发送位（运行中发送位换成停止），用户不必到消息流里找。
- 用户消息：右对齐，**浅灰 `bg-hover` 胶囊**（radius 9999 / 20px，深色文字），不用黑底白字。
- 助手消息：左对齐，无气泡，15–16px 正文；可含标题、列表、卡片。
- 生成式 UI（智能体 `uiFormat=openui`）：围栏内程序使用项目组件与令牌，块间距16px；围栏外散文照常走Markdown，按出现顺序排列。`@ToAssistant` 才发新用户消息，原生变量/查询/修改由OpenUI运行时执行，不覆盖输入草稿。每段的查询错误、重试、保存失败与待批入口就近显示，不能把会话级OpenUI审批指到运行审批页。批准工具时明确显示工具名、8小时会话范围；运行级审批仍沿用原语义。补丁输出期间保留上轮完整界面，不把半个root合并成新界面。
- 生成式内容采用OpenUI官方shadcn示例的组件组合，官方chat库补足示例未覆盖的指标卡等。底层仍是Base UI与本项目令牌，不引入Radix或第二主题；组件契约不为视觉调整而改名/改字段。
- CardBlock随消息容器宽度响应：480px以下单列，更宽两列；奇数末卡跨满。主图与复合卡内图分别按256px/192px默认空间表达主次，显式height优先。Carousel 复用 shadcn 轨道；`responsive=false` 时按官方固定卡宽 small 280 / medium 320 / Overview 240（容器 ≤30rem 时 200），不做视口推断。数字列右对齐且不折断，长描述列允许换行，横滚仅在表格内部。
- TextContent字号由外层语义贯穿Markdown，普通Text常规字重、BoldText加强。Markdown 与 OpenUI 共用真实 `streaming` 状态：流式中允许调度器跳过中间渲染，终态直接渲染完整文本；只有外层渲染树稳定，Streamdown 在模式切换时会重挂内部代码块等节点。表单用官方 Field/FieldGroup 组合，invalid 经 Base UI `Field.Root` 传到真实控件。普通图片保留3:2占位并用 contain 完整容纳，ImageBlock 保原图比例，不统一固定高度裁切。
- 工具调用按轮分层：每轮的正常工具调用集中到该轮一个可折叠的「执行过程」区，使用按官方 shadcn `Trace` 源码落地的 `TraceCollapsible` / `TraceLine` / `TraceIcon` / `TraceTitle` / `TraceDescription`，不另写自绘折叠行；折叠头保留单行摘要，展开项沿用单行「图标 + 名称 + 状态 + 耗时」，点击展开参数/结果，不用厚边框。官方 registry 没有独立 Thinking 组件，reasoning 也归 `Trace`；只有事件流实际提供 thinking 数据时才渲染，不伪造。顶层正文的内容与顺序不变，不把正文并入折叠区。审批、原生澄清提问、失败工具、缺失结果与 `error` 始终在折叠区外可见且只出现一次，不从折叠区重复渲染；失败与超时原因常驻显示，不依赖展开。
- 任务清单：当本轮有模型确认的步骤清单时，在助手正文与工具项之后、该轮运行读数之前追加一块紧凑清单，独立于执行过程折叠、不随折叠隐藏，也不复用工具行的展开结构，不做成卡片。标题行只有 16px `ListChecks` 图标与等宽 `xs` 的 `已完成/总数` 计数（常规元信息档），可见计数只出现这一次（屏幕阅读器可另读完整句子），不再另起一行写共 N 项；下面按原顺序列步骤，行距 `gap-1`，步骤文字用 `md` 正文档。每步固定 16px 图标 + 文字：已完成用 `CircleCheck` 与成功色、进行中用 `LoaderCircle`（沿用既有旋转）、待处理用 `Circle` 与 `subtle`；完成与待处理文字用 `muted-foreground`，进行中文字用 `fg` 并显示 `activeForm`。状态靠图标形状、文字色与屏幕阅读器的状态前缀共同表达，不只靠颜色。本轮没有确认清单或清单已被清空时不渲染，保留原运行/工具状态行，不出现空态或占位。清单只陈述模型报告的进度，不使用「已完成任务」「全部完成」等质量结论，也不因运行结束改写步骤状态；失败或超时原因仍在该轮常驻显示，不以清单状态掩盖；不新增字号、色值、圆角或间距令牌。
- 底部输入区常驻，沿用欢迎态的分层输入与底部操作布局，保持原有流式跟随、分支、停止和历史恢复逻辑。发送是明确动作：新的一轮用户消息出现时视图直接回到最新，即使此前已向上翻看历史；阅读历史期间的流式增量不会抢滚动。
- 输入区提供“添加资料”常规 ghost 图标按钮与多选文件框，已选文件在输入框上方显示名称、大小和移除；类型/数量/合计超限时在输入区内用 `role="alert"` 明确说明，不弹独立面板。正文与附件至少一项即可发送。用户消息把附件显示为紧凑标签（名称、大小，有服务端 id 时整枚可下载）；附件读取/上传失败保留本次选择。不要另做资料云盘、PDF 预览器或拖放/粘贴入口。
- 会话头部参考用户截图：标题只占约 8 个中文字符宽度（`max-w-[8em] truncate`），完整标题保留在 `title` 与可访问文本中，紧随一个常规 32px「会话操作」更多菜单；不把标题拉满整行、不把菜单推到右边。菜单复用重命名、Fork，删除需确认且排队/运行中的会话不可删；未保存的新会话禁用菜单。消息区与会话历史头部都不画底部横线，靠一致的对齐与留白形成整体。历史头部不再显示「对话」等重复标签，直接用专家选择占据该位置，右侧保留新建与抽屉关闭，搜索与列表紧随其下。
- 历史搜索使用居中浮层，跨全部专家检索会话标题、会话 ID 与消息正文；每条结果同时给出专家、标题、时间与命中的正文摘要，定位信息不另起一行重复。上下方向键移动选中项、Enter 打开，输入法组合期间的 Enter 不触发；Esc、关闭按钮与外部点击走同一关闭路径并把焦点还给触发器。关闭浮层或发起新查询时取消上一轮未完成请求；结果分页使用游标。打开结果后进入目标专家的目标会话并保留当前未发送草稿；只定位到会话，不承诺跳转或高亮正文中的具体命中消息。
- 专家选择在欢迎态与已有消息/历史会话中仍可用。未发送输入按会话隔离保存到当前标签页的 sessionStorage，刷新可恢复；切换会话不串草稿，新建会话不继承旧会话；切换到另一位专家表示进入该专家的新对话：历史列表按新专家刷新，清空当前视图的旧消息、运行与审批上下文，URL 去掉旧 conversation，回到欢迎态；原会话保留在原专家历史中，未发送输入带过去并继续保留。再次选择同一位专家不清空会话。切换只解除旧事件流订阅，不自动取消后台运行。
- 桌面会话列表默认 240px，可在 200–360px 间调整；使用 react-resizable-panels 的 `collapsible`、`panelRef.collapse/expand` 和现有 `useDefaultLayout` 记住布局，收起为 0px，不另建宽度存储。历史与内容使用同一 `bg-surface`，只有 1px 竖向分隔；隐藏时分隔不再占位、历史控件不可聚焦，展开与收起按钮正确交接焦点。标题只在当前可见位置出现，始终一个 h1。

## 7. 侧栏

实测（2026-10-21，CDP）：

- **展开 272px**，内边距 `16px 12px`，分组间距 18px；过渡 `160ms cubic-bezier(.22,1,.36,1)`，同时过渡 width / height / transform / background-color / box-shadow。
- **收起 68px**，内边距 `16px 18px`；条目变成 32×32 图标块，文字标签 `opacity 0 / width 0`（90ms 过渡），悬停/选中态落在图标块本身而不是整行。
- 顶部：展开品牌区高 32px，显示完整艺术字组合，与右侧折叠按钮同高同中心线；收起为 32×32 木工矢量标记。收起状态保持原逻辑：悬停时标记淡出，同位置换成展开按钮（32×32，radius 7，140ms），点击展开侧栏，不触发 Logo 切图。

## 8. 其他页面

1. 同一个外壳：4px 外边距、16px 圆角、纸白底。
2. 顶部一行：名称 + 主操作，不超过 56px。
3. 一般列表用行：行高 56–64px，1px 分隔线，悬停 `rgba(0,0,0,.02)`。专家、技能、连接器、插件、知识库五类资源共用资源中心：类型导航、搜索与管理操作使用同一套位置和交互，排列参考用户指定的 https://www.workbuddy.cn/app/experts，视觉仍使用本规范令牌。
4. 资源中心沿用 `ResourcePage` 的顶层布局，类型入口使用有名称的导航与真实路由链接，当前项通过 `aria-current="page"` 表达，保留 line 页签外观；页内任务切换仍使用 Base UI Tabs。资源操作区固定两行：顶行为类型切换、搜索与创建/导入等管理操作；次行左侧为来源切换与结果数量，右侧为筛选与排序（没有来源切换的资源只显示数量）。技能「内部 / 市场」用浅灰分段控件区别于资源导航；市场保留既有「总榜 / 趋势 / 新热」榜单切换，搜索时隐藏榜单切换、只展示搜索结果。内资源继续使用卡片：网格间距 16px，随可用宽度显示 1–4 列。技能市场使用轻量两列条目，窄桌面降为一列；每条只呈现名称、真实来源与真实安装数，安装使用描边按钮，不添加宣传区、推荐语或无数据支持的热度、市场与分类。网格首格固定放「新建」扇形卡：六张角色插画在卡片中央叠成一摞（各自微旋转 −5°…+5°），悬停/键盘聚焦时按次序向两侧展开成扇形（外侧 −18°/+18°、内侧 −4°/+4°，位移 −80…+80px、−20…+16px），`transform 300ms`、`box-shadow 150ms`、外侧 chip 逐个 `transition-delay` 递增；整卡为虚线边框、悬停转浅灰底。角色插画允许保留既有低饱和配色，卡框、文字与控件统一遵循 §2 的纸白与工具灰主题。点击进入新建流程（仍是 Dialog）。专家配置使用独立路由页 `/agents/$agentId`（页头头像 + 名称/描述 + 返回/删除），不再用右侧抽屉；技能与连接器的编辑仍用弹层或抽屉，插件与知识库详情使用独立路由页并执行 §9「阅读工具栏」契约。
5. 表格：表头使用 `xs` 12px 弱色，常规单元格沿用共享 Table 的 `sm` 13px，数字右对齐 + 等宽；`base` 14px 用于列表与卡片标题，不覆盖表格数据字号。
6. 主按钮：黑底白字，常规32px高、9px圆角；紧凑操作28px高、7px圆角。发送按钮沿用共享图标按钮。
7. 账号入口采用整页纸白底与无外框窄表单，最大宽 320px；Logo 居中显示高 96px，与表单间隔 32px。去掉可见「登录」标题，保留屏幕阅读器用的单一 h1「进入 PACE」，文档标题为 PACE。账号、密码和主按钮高 44px；字段组间距 20px，按钮文案为「进入工作台」/「正在进入…」/「重试」。不加宣传文案、额外入口或装饰性卡片，保留完整校验、错误提示与提交保护。

## 9. 组件与交互契约

本节是同类 UI 的唯一约定。开发中发现缺口时在此补齐，同时更新共享组件与现有调用方；并行任务沿用相同契约。官方原语负责交互和无障碍，项目令牌负责视觉。**文案与信息密度不在这里逐条规定，统一遵守 §10「信息表达」硬性规约。**

| 场景 | 统一约定 |
|---|---|
| Input / Textarea / Select / Combobox / 搜索 | 单行高 32px，圆角 9px；多行与多选可随内容增高。默认 1px 浅灰边框，无投影；字段布局通过 Field / FieldGroup 表达 |
| 焦点与边框（统一规则） | 每个控件**只允许一层焦点信号**，全站同一套：① **有既有边框的输入类**（Input / Textarea / Select 触发器 / Combobox / InputGroup 搜索）→ 聚焦时把那条 1px 边框换成实色 `ring` 令牌，**不再加 2px 光环**；错误态同样只把这条边框换成危险色。② **无边框或边框透明的按钮类**（Button / TabsTrigger / Toggle / Switch / Checkbox / Badge / 折叠触发 / 拖拽手柄等）→ 用单层 `focus-visible:ring-2 ring-ring`，并且必须带 `focus-visible:outline-none`（避免叠加全局 `:focus-visible` 的 2px outline）。③ 全局 `:focus-visible` 只作兜底。原则：**边框与光环二者取其一**，任何控件不得同时出现「边框 + 光环」两层。InputGroup / Combobox 由外框承担焦点，内部输入不重复画框。自动校验：`pnpm lint:focus`（已接入 CI，检查输入类原语无 `ring-2`、`focus-visible:ring-2` 必配 `outline-none`）。 |
| 错误 / 禁用 | 错误使用危险色边框与字段提示（输入类不叠 ring），Field 的 data-invalid 与控件 aria-invalid 同步；禁用同步 data-disabled 与 disabled，保持可读，提交中关闭按钮与取消均不可丢弃请求 |
| 按钮 | 常规操作 32px / 9px 圆角；紧凑操作 28px / 7px；工具栏创建使用常规主按钮，卡片配置/编辑使用紧凑 outline，取消使用 outline，删除与放弃使用 destructive |
| 卡片 | 五类资源的卡片视图共用 40px 头部图标、标题与描述的横向头部；描述最多两行；能力/标识放内容区，辅助信息与配置/编辑动作放页脚；标题与显式操作可打开同一编辑入口，删除统一放操作菜单。专家头部图标改为 40px 圆形插画头像（见下条），技能、连接器、插件与知识库仍用中性图标。专家有角色时，标题右侧显示角色小标签（`bg-chip` 弱色胶囊），与参考页一致 |
| 专家头像 | 标准岗位直接对应固定插画头像，显式岗位优先于名称与描述；只有历史数据尚无标准岗位时，才使用名称关键词或 slug 散列。数字分身使用专属双人轮廓头像。卡片用 40px，独立配置页页头用 44px，均圆形 `rounded-full object-cover`，纯装饰 `alt=""`。插画的低饱和背景是图形色彩例外 |
| 标准岗位 | 角色来自 `packages/shared/src/agent.ts` 的 `AGENT_ROLES` 单一目录；创建与编辑用 Select，列表与详情显示相同角色标签。空角色统一为「通用助手」，不根据名称猜测并写入岗位。专家列表的工具栏在「启用状态」之外并列「角色」筛选（选项即 `AGENT_ROLES`），两者都写入 URL `search`；空态「清除筛选」同时清空关键词、状态与角色。扩展岗位在同一目录登记，并同步头像映射与验证；不允许随手输入未登记岗位。历史岗位可原样显示，修改时选择标准项 |
| 数字分身 | 在专家网格中提供独立创建入口，使用专属头像；创建表单按头像、名称、工作背景与表达方式组织，沿用现有模型与专家保存能力。数字分身是明确的角色类型；工作背景存为系统提示词。参考项目的记忆学习、资料导入、平台连接与记忆可见范围尚未实现时，不显示假进度、假数据或不可用的设置项 |
| 搜索 / 筛选 / 排序 | 搜索可清除，输入 replace URL；筛选排序 push URL；下拉列表统一在触发器下方展开。空结果给出清除筛选动作，错误给重试，加载用共享骨架 |
| 弹层 | DialogShell 管理标准标题、描述、关闭按钮与可滚动内容；Sheet 保留复杂配置与版本历史。右侧操作顺序为取消、主操作；dirty 状态下取消、Esc、外部点击、关闭按钮使用同一放弃确认；请求中禁止关闭；关闭后返回实际触发器 |
| 专家配置页 | 独立路由页而非抽屉：PageHeader 左侧 44px 头像、标题、角色标签，右侧「返回列表」与主操作「开始对话」；描述紧跟页头（同一 `flex flex-col gap-2` 组），仅非空时显示，不另占 Page 的 20px 区块间距。其下为**任务页签**（配置 / 长期记忆 / 项目规则 / 输出风格 / 完整文件 / 运行统计），任务、当前分区与选中文件写入 URL search；用 line 页签且不换行（固定 32px，避免多行溢出）。**配置**任务为两栏（`md:grid-cols-[220px_minmax(0,1fr)]`）：左栏只列五个配置分区（身份/行为/能力/权限/运行限制），不加模型、权限枚举或计数摘要；右栏是**一张白底详情卡片**（`rounded-card bg-surface px-6 py-5 ring-1 ring-line`），只渲染当前分区。配置工具栏只在配置任务显示（启用、未保存、去修正、保存更改、版本历史、更多），保存范围就是五个分区；版本入口命名为「配置版本历史」。克隆、导出与删除都放「更多」菜单。**完整文件**任务才展示按根文件 / 技能 / 子智能体 / 规则 / 输出风格分组的文件目录与只读预览；记忆、规则、输出风格直接使用各自的列表 + 编辑器，不再外套第二层导航。短字段（模型、推理强度、权限模式、运行限制、回复格式等）使用横向设置行：标签在左、控件在右，控件宽度按内容收敛；长提示词与文件内容仍用纵向 `Field`，标签在上。不把所有字段统一成标签上方。靠 `FieldGroup` 的 `gap-5` 编码结构；**不逐字段标注落盘路径（`→ …`）或「仅运行时」**，分区标题单独一行、不加摘要不用分割线；能力分区用加粗子分组（MCP Servers / 技能 / 子智能体）+ 右侧计数。行为分区顺序为模型 / 推理强度 → 系统提示词 → 折叠草稿预览。校验失败先切到配置任务与出错分区再聚焦字段；切换任务、切换配置分区与文件切换都保留主配置草稿。离开页面与切换任务受合并后的 dirty/pending 保护，子面板保存不借用配置保存按钮 |
| 专家配置页间距 | 以实屏为准的固定档位，全部取自现有 `gap-*`/`px-*`/`py-*`，不新增令牌：页头与描述 8（`gap-2`）；AgentEditor 主块之间 20（`gap-5`）；任务/操作行组间 12、操作按钮间 8，行下方留 12（`pb-3`）并保留 1px 底线；配置与完整文件两栏 220px + 20 间距、顶部对齐；分组标题到内容 16（`mt-4`）、组内子组 16（`gap-4`）；字段 grid 20（`FieldGroup gap-5`）、纵向字段标签到控件 6（`gap-1.5`）、横向设置行标签与控件同一行并保持 12（`gap-3`）；详情/子面板卡片内容内边距 `px-6 py-5`（24/20）；记忆、规则、输出风格内部列表 + 编辑器同样 220px + 20、顶部对齐 |
| 专家编辑控件 | 主配置、记忆、规则和输出风格共用控件语义：保存为常规 32px `default` 石墨主按钮，未修改时禁用，不单独改禁用颜色；返回、子面板新建和取消使用常规 `outline`；历史与更多使用 32px `ghost` 图标按钮；删除使用 `destructive` 并有可访问名称。并列操作 `gap-2`（8px）、工具栏分组 `gap-3`（12px）；带文字的图标用 `data-icon="inline-start"`，尺寸由共享组件管理。子编辑器统一标题左、操作右（次操作在前、主保存在后）、字段在下；字段用 `FieldGroup gap-5` 和 `Field gap-1.5`，每项有可见且关联控件的标签；短字段用横向设置行、控件宽度按内容收敛，长文本与文件字段纵向排列、控件填满字段宽度。标识和 Markdown 可等宽，但不覆盖共享输入字号（13px），不单独覆盖控件的高度、圆角、颜色或焦点。权限工具使用共享 Toggle 的中性选中态，安全警告另行保留。保存期间字段和冲突操作一并禁用，错误或失败保留草稿，各编辑器继续只保存自身资源 |
| 阅读工具栏 | 插件详情、知识库详情与会话成果共用 `ReaderToolbar`：阅读/源码切换、复制、下载保持同一顺序与同一控件身份；业务差异留在工具栏之外（插件文件树与面包屑、知识库文件侧栏与文档元信息、成果版本选择）。插件与知识库的文件侧栏可收起。会话成果右侧栏保持 320px，不因统一工具栏加宽 |
| 知识库卡片 | 整卡可打开详情：详情链接铺满整张卡片并覆盖标题与内容区，操作菜单浮在覆盖层之上，点菜单不跳转；不出现嵌套交互元素，链接保留指向知识库的可访问名称 |
| 知识库文档工具栏 | 「上传文件」是工具栏主操作；上传文件夹、手写文档、导入网址收进相邻的次级「导入」下拉，不与主操作并列。上传进度、单文件限制与逐项失败提示沿用现有行为 |
| 知识库来源 | 新建来源为「选择 provider → 配置」两步，编辑直接进入配置且来源类型只读；创建与编辑共用同一表单。来源行显示 provider、目标范围、cron 与最近同步状态。配置字段分为「连接」（名称、地址、凭证）与「同步范围」（范围行、cron、删除策略） |
| 定时任务创建 | `DialogShell` 按两栏分区：左侧任务内容（名称、提示词），右侧执行条件（仅列已有专家、cron 按 UTC 解析、启用开关）；危险或授权语义就近显示，不添加不存在的时区选择、授权方式或策略项。窄宽度下两栏顺序堆叠，控件沿用共享规格 |
| 新建扇形卡 | 「新建专家」卡的插画扇形是页面级唯一例外动效：静态叠放、悬停/聚焦展开，遵守 `prefers-reduced-motion`（全局已将其压到 0.01ms）；不用入场动画，只在 hover/focus 触发，键盘聚焦与鼠标悬停同等生效 |

对话输入区采用 §6 的多行 InputGroup 形态；代码/标识可用等宽字体。除此之外，页面不单独覆盖同类控件的边框、焦点、圆角和高度。

### 全站页面布局契约

以「专家·技能·连接器」页为组件尺寸、间距与操作区基准，以下规则覆盖所有页面。页面按功能组织内容，不另定同类元素的标准。

- AppShell 统一水平 12px 内边距、全宽内容与独立纵向滚动；不再按路由限制 960px。对话消息轴线保留 728px，登录表单是唯一居中窄表单。
- Page 主区块间距 20px；PageHeader 顶部 12px、最小 44px，左侧标题，右侧常规 32px 操作，操作间距 8px。指标、说明、筛选另放下一行，不把多层读数塞进标题行。
- PageToolbar 控件间距 12px、可换行；搜索桌面 224px、筛选 144px、排序 128px，窗口收窄时可收缩为整行。使用正常布局间距，不写负外边距补偿。
- PageSection 内部间距 16px，区块分隔后顶部 20px；资源网格间距 16px。工作台用于摘要与异常定位，运行/审计保持数据表，评估与健康按功能分区，详情保留步骤与检查器，不机械卡片化。
- 工作台只保留一套日常概览：统计窗口说明放在指标组标题处一次，概况、专家指标和趋势统一使用最近 7 个 UTC 自然日（含今天）；四张卡片为运行次数、运行成本、专家、连接器，连接器数量只含资源中心可管理项，卡片内不再重复窗口；不再另设任务总数看板或快捷入口。待处理事项（审批与失败运行）合并为唯一入口，空态给下一步动作，不写“暂无”。正常健康指标不占首页，仅当前队列积压/等待、指标缺失或刷新失败时显示一行并链接健康页；队列历史 failed 是保留计数，只在健康页解释。主区展示带整数运行次数刻度的运行趋势与最近运行；趋势提供可键盘展开的同源数据表，日期、运行、失败、成本与 token 均可读取，表格仅在容器内横向滚动。完整专家数据放下方，专家名称直接链接对应详情。概况数字不与导航按钮混排，长列表不得把关键入口挤出首屏。
- 窗口收窄时保持无页面横向溢出；两列功能区在空间不足时顺序堆叠，表格必要时只在表格容器内水平滚动。所有加载、错误、空态与正常态沿用同一骨架，始终一个 h1。
- 页头操作使用常规 default/outline，区块与行内操作使用 sm；应用页面不为同种按钮覆盖圆角、高度与焦点。聊天输入区的页面级规格只采用 §6 已定义值。

### 固定视觉值与场景例外

- §1–8 的尺寸、圆角与间距沿用既有基准；色彩以本规范 §2 为准，调整统一从 styles.css 的语义令牌进入。
- `subtle`（38%）保留给装饰性细节；表头、时间、计数、帮助文字、错误恢复说明与可操作标签使用 `muted-foreground`（不透明中性灰 `#666666`，见 §2）或 `fg`。38% 弱色不用于承载需要阅读的信息，中性灰辅助文字保持至少 4.5:1 对比度。禁用状态保留其既有例外。
- 控件沿用桌面字号：Input / Textarea 使用共享 13px 语义字号；多行代码编辑器可保留等宽排版，但不关闭浏览器缩放。
- 聊天继续使用 728px 消息轴线与多行输入区；运行、审计、评估结果使用数据表；资源中心的内资源使用卡片，技能市场使用轻量条目列表。统一的是令牌、控件与状态反馈，不是这些场景的布局形态。

### 可访问交互与异步状态

- 表格保留可识别的行、列与表头关系；排序暴露当前方向，长值可换行或在详情中完整读取。窗口收窄时只滚动表格容器；列排序同时提供拖拽、键盘与点击调整路径，锁定列不能被历史偏好隐藏。
- 页面标题、弹层标题、说明和下拉选项允许长文本换行。弹层头部保持可达，内容区受动态视口高度约束并隔离滚动。Popover（包括表格列设置）通过 Base UI 的 `--available-height` / `--available-width` 限制可用空间，超长内容内部滚动并设置 `overscroll-contain`；这是短视口适配，不改变固定控件尺寸与圆角。
- 保存期间禁用受该请求影响的表单字段及冲突操作，字段同步 `data-disabled`。同一 pending 标识只能管理一个在途请求；要么串行禁用，要么按对象分别跟踪。乐观更新不得通过卸载/重建确认框清除请求保护。
- 校验在提交时明确显示字段错误并关联控件；数字显示数值边界，列表显示项数，文本显示字符数。键值与 JSON 编辑不得静默丢弃无效内容；必填错误需给出补全路径。
- 原生澄清提问放在对应工具调用位置，以问题、选项与回答动作组织；复用单选、复选与文本输入，提供「其他」及「暂不回答」。已回答/关闭状态只读；运行详情复用同一组件。提问回答不表达业务工具已获批准，不与审批动作混用。
- 状态不只靠颜色表达；消息需提供发言者语义，审批需准确对应连接器与工具。辅助数据失败也应显示重试入口，缺失指标不得伪装成零；ResourcePage 的资源数量仅在列表请求成功时显示，加载或失败时显示相应状态。已失败任务不得提示仍在自动等待。
- 会话切换使旧请求与事件流失效，晚返回响应不得覆盖新会话；历史尚未加载完成时不能追加发送。连接中断不是任务终态，保留运行标识与停止入口，并从服务端状态收尾。输入法组合输入的 Enter 不触发发送。
- 错误 toast 保留到主动关闭；复制失败提供手动复制说明。焦点提示不得被页面覆盖移除，关闭弹层返回实际触发器，触发器消失才使用后备入口。
- 登录状态检查期间的全局骨架与失败分支也保留当前路由的单一 `PageHeader`（可视觉隐藏）和文档标题；未知路由明确命名为「页面不存在」。
- `DialogShell` 中的表单提交校验失败后，等待字段错误渲染，再聚焦内容区首个 `aria-invalid` 控件并滚动到该字段；复杂专家 Sheet 继续由分区导航定位错误，避免把隐藏分区当作可见表单。
- 强制颜色模式下，控件阴影焦点会被系统移除，统一恢复系统 `Highlight` 的 2px 轮廓；这是系统可访问性适配，不改变普通模式的中性灰 `ring` 与既有布局值。
- 多选 Combobox 的已选项区域有分组名称，每个移除按钮明确命名「移除 + 项目名」；Chip 与输入提供 Base UI 的方向键、Backspace / Delete 操作说明，不能只给外层 Chip 命名。
- 编辑草稿必须与打开时的版本基线绑定。409 冲突不得自动用最新版本号重发旧草稿；提供明确的重新加载动作并确认放弃旧草稿。dirty 或保存中也保护路由离开与刷新，不能只保护弹层关闭。
- 键值编辑拒绝重复键并指出行号；环境变量区分大小写，HTTP Header 不区分大小写。后端不支持清空的可选配置不得显示可保存的「恢复默认」或把空值伪装成保存成功。
- 历史会话重开需等待最新历史并恢复最近运行与审批上下文；运行进入终态时最后刷新一次审批，再停止轮询。发送被接收后刷新服务端会话列表；只保存批准的按钮命名为「批准」，不承诺自动继续运行。
- 评估跑批中断原因与已完成结果同时显示，部分通过不得掩盖未完成用例；登录凭据错误与会话失效分别提供恢复说明。

- 页面身份按实际匹配路由确定；命中 `$` 的未知地址即使带有已知路径前缀，也统一显示「页面不存在」文档标题和加载/失败标题。
- 专家回滚与常规保存共用 pending 生命周期；回滚确认明确说明未保存草稿会丢弃，等待期间不可关闭历史、继续编辑或离开路由。版本差异须完整显示目标文本与数组内容，导入返回的提示须可逐条阅读。
- 专家配置的任务切换与路由离开共用同一份 dirty/pending：主配置草稿与当前子面板（记忆 / 规则 / 输出风格）的未保存内容都算数。主配置随页面常驻，切换任务保留草稿；子面板草稿会随任务卸载，切换前确认放弃。路由离开两种草稿都要保护，保存中不得切换或离开。各子面板的保存只负责自身资源，配置保存按钮不跨任务保存。
- 聊天离开页面保留未发送输入，清理会话和运行上下文；历史终态恢复结果与失败原因，未被服务端接收的发送不显示指向旧运行的「本次运行」。连接器名称缺失时审批显示其 ID。
- 运行列表沿用当前接口的最近 100 条范围；达到上限时明确说明范围及列排序只作用于当前记录，不承诺接口尚未提供的完整历史分页。

## 10. 信息表达（设计规约·硬性）

> **一句话：删掉标语、辅助文案和次级标签。"Cut taglines, helper text and secondary labels. If a screen needs them to make sense, fix the layout."** 界面必须靠这些文字才看得懂时，先改布局，而不是补文字。
>
> 这是每个页面、区块、卡片、弹层的**默认约束**，不是建议。视觉做得再对，只要靠一堆次级标签和说明文字来解释结构，就算没遵守本规约。评审 UI 时先过这一节。
>
> 布局与文案调整同时遵守 [CLAUDE.md「决策标准」](../CLAUDE.md#决策标准) 的 UX/DX/AX 原则，并保留现有功能。

### 10.1 核心规则

1. **结构先由布局承担。** 先用分组（group）、对齐（alignment）、间距（spacing）、层级（字号/字重/底色）表达关系。若当前布局表达不了某个关系，**先改布局**（分组、对齐、间距、标题层级、容器边界），不要用加文字当补丁跳过这一步；确认布局确实无法承载后，才补必要的文字（见 10.2）。
2. **不重复解释。** 页面标题、分区标题、字段标签、占位符、徽章、计数、可见控件已经表达的信息，不得再用副标题、行内说明或第二次标签重复一遍。
3. **文字只为「新信息」存在。** 一段可见文案必须二选一：给出布局无法表达的新信息，或指导下一步操作。两者都不满足就删掉。
4. **信息层级 = 层级信号，不是满屏小字。** 用少量强信号（容器边界、一级标题字号/字重、两列对齐）分层；不要给每个字段都挂一行灰色小字，那会把层级摊平成噪音。
5. **空态/错误/加载也遵守。** 空态说明「这里是什么 + 下一步做什么」，不复述「暂无/还没有」；错误给可恢复动作；加载给共享骨架。不写承诺式废话。
6. **删词不等于删信息。** 实现细节类信息（落盘路径、字段映射到哪个文件）**一次讲清即可**——放进「完整文件」页签、展开区或 tooltip，不在主界面逐项重复。

### 10.2 允许保留的文字（不可为"精简"而删除）

- 表单字段标签、必填标记、格式/约束提示（如「创建后不可修改」）。
- 校验错误、禁止/危险操作说明（如「此操作不可撤销」「放行内置工具会扩大攻击面」）。
- 影响决策的安全/权限信息、状态与结果（步骤、状态、耗时、工具 IO、审批与实际执行对应关系）。
- 无障碍名称、`aria-*`、`sr-only`、按钮/链接文案、placeholder。
- 空态里的**下一步动作**与其按钮。

> 精简可见文案时，交互原语的无障碍契约（标签、名称、状态播报）仍须满足，见 §9 与「可访问交互与异步状态」。

### 10.3 优先做法（用这些代替加文字）

| 想表达 | 用布局 | 不要用 |
|---|---|---|
| 字段属于哪一组 | 分区标题 + `FieldGroup` + 间距 | 每个字段旁贴分组名/路径标签 |
| 谁更新、什么时间、什么状态 | 对齐的列/徽章/时间戳 | 行内叙述「该记录于…更新为…」 |
| 数量/汇总 | 徽章、计数、列、指标卡 | 另起一行「共 N 个…」重复 |
| 层级关系 | 容器边界（卡片 vs 画布）、字号/字重 | 到处加同色小号说明字 |
| 空态引导 | 标题 + 一个主操作按钮 | 「这里还没有任何内容，请先去 X 添加」 |

### 10.4 反模式（出现即改）

- 页面级副标题只是把路由名/标题再说一遍。
- 卡片/行下方再挂一行复述可见控件、类型或数量的小字。
- 逐字段 `→ 某文件路径`、`仅运行时` 之类落盘/实现标签贴在表单上。
- 空态写「还没有/暂无…」+ 一大段说明，却不给下一步按钮。
- 同一个计数既在徽章又在旁边文字里出现。
- 用次级说明去弥补层级不足，而不是改分组/间距/标题字重。

### 10.5 提交前检查清单（逐条对照）

- [ ] 删掉任意一行可见说明后，界面是否仍然清楚？是 → 删掉。
- [ ] 每个可见副标题/说明是否都在提供**新**信息或**下一步**？否 → 删掉。
- [ ] 层级是否靠分组/对齐/间距/字号区分，而不是靠更多灰色小字？
- [ ] 空态是否「是什么 + 下一步动作」，没有复述「暂无」？
- [ ] 实现细节（路径、文件映射）是否只讲了一次（放完整文件/展开区/tooltip）？
- [ ] 删除文案后，字段标签、`aria-*`、`sr-only`、错误与危险提示是否完整？否 → 补回。

## 11. 动效

- 交互过渡 90–160ms，统一 `--ease-out-soft`（`cubic-bezier(0.22, 1, 0.36, 1)`）；只过渡实际变化的属性，禁止 `transition-all`。
- 侧栏宽度过渡 160ms；标签淡出 90ms；展开状态 Logo 切图为 300ms 轻推接力；收起状态保留 Logo 与展开按钮互换的 140ms 过渡。
- 允许的动效只有局部交互与状态反馈：悬停背景、展开折叠、浮层显隐、流式光标、复制/安装等结果反馈。
- 浮层（Dialog / Sheet / Popover / 菜单 / 选择器 / Combobox / Tooltip）统一由 Base UI 的 `data-starting-style` / `data-ending-style` 驱动透明度过渡 150ms，官方在动画结束后卸载；Positioner、Portal、焦点与关闭保护保持不变。
- Sheet 保留各 side 的定位与尺寸，仅淡入淡出，不做位移；Switch、加载/运行状态等控件必要状态保留其原有位移或颜色过渡，不属于装饰动效。
- 骨架屏保持静态，不做呼吸；消息滚动按钮只做可见性淡入淡出，不位移、不缩放。
- 无页面入场动画、无装饰位移、无呼吸点；不改尺寸、色值、布局与业务行为。
- `prefers-reduced-motion` 下全局把过渡/动画时长与延迟归零；JS Motion 仍由各调用方读取 `useReducedMotion` 自行收敛。

## 12. 实现技术栈（硬性）

视觉由上文的数值决定，交互与结构由下列库决定。**不得手写这些库已经提供的东西**：

| 需求 | 唯一实现 | 约束 |
|---|---|---|
| 控件、表单、浮层 | shadcn/ui（`base-nova`）+ Base UI | 先复用或安装官方组件，共享视觉由 `@theme` 语义令牌控制 |
| 图标 | lucide | `LucideProvider` 在 `App.tsx` 统一设 `strokeWidth={1.75}`、`size={16}`，组件里不要再逐个传 |
| 动效 | Motion（`motion/react`）+ Base UI 状态过渡 | 局部交互与状态反馈用 CSS transition（90–160ms、`--ease-out-soft`；浮层用 `data-starting-style` / `data-ending-style`）。需要布局开合时用 Motion：`duration` 0.15–0.2、`easeOut`，并读 `useReducedMotion` |
| 可拖拽分栏 | react-resizable-panels v4 | `Group` / `Panel` / `Separator`；用 `useDefaultLayout` 持久化；分隔条就是 1px `border-line`，不加把手 |
| 拖拽排序 | dnd-kit | 必须带 `KeyboardSensor`，拖拽手柄有可访问名称 |
| 客户端状态 | Zustand | 只放**跨组件、非服务端**的状态；服务端数据一律 TanStack Query |
| 路由与 URL 状态 | TanStack Router | 筛选、分页、选中的 tab 走 `validateSearch`，不要塞进组件 state |
| 类名合并 | `cn`（`lib/cn.ts`） | 唯一实现，不引入 clsx / tailwind-merge 的第二份 |
| 生成式 UI 渲染 | `@openuidev/react-lang` 的 `<Renderer>` | 组件实现全部映射到 shadcn/ui；官方解析、响应式、表单与Query/Mutation运行时负责交互。业务不加载 `@openuidev/react-ui` 的视觉层，该包仅作开发期契约对照。围栏外散文仍走Markdown |

- 项目圆角：外壳与卡片 16 / 行与常规控件 9 / 图标按钮 7 / 标签 6。底座内部细节沿用官方结构；`--radius` 为 9px，InputGroup 的内部按钮经 `calc()` 推导为 6px。共享映射见 `styles.css`。
- shadcn 原语的语义色（`bg-popover`、`text-muted-foreground`、`bg-accent` 等）已全部映射到统一低饱和度主题令牌，**不要在组件里改回具体色值**。
- shadcn 定制顺序：内置 variant → 局部布局 → 源码中的语义 variant → 有实际复用需求的应用组合。底座组件放 `components/ui/`，应用组合放 `src/components/`（如 `ConfirmDialog`）。允许改源码，但保留原语的 `aria-*`、焦点管理与键盘交互，只改外观 token；安装/更新前对比 git diff，`--overwrite` 会覆盖既有定制。

## 13. 禁止

- 卡片套卡片、彩色边框、彩色左边条。
- 渐变、玻璃、阴影堆叠（外壳无阴影；输入框用 composer 阴影，浮层统一用 overlay 阴影）。
- emoji 当图标。
- 一页多个同等权重标题。
- 将 Logo 的黄色或木色铺成高饱和度的大面积页面、按钮或选中态，或为各页面另造一套强调色。
- 用次级标签/说明文字去重复布局、标题或控件已经表达的信息（违反 §10）。
