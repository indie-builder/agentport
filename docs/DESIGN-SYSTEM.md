## 1. 整体结构

```
根容器 #FBFBFB（画布 canvas）
├─ 侧栏（默认收起 48px；临时预览 224px 覆盖正文；固定展开 224px 推开正文；不透明浅石青底）
└─ 主区：平铺全幅，表面 #FFFFFF，无外边距、无圆角、无描边、无阴影
   └─ 普通页面：内容左右 24px、底部 24px，顶部最小 48px 页头
      └─ 聊天：历史／消息列／成果三栏从工作区顶部并排开始
         ├─ 历史：默认收起 0，首次展开 240px（可 200–360px）；展开头部 56px（专家选择 + 新建），下方搜索与列表
         ├─ 消息列：56px 头部（左右 24px）在列内，消息与 Composer 在下；832px 阅读轴线（含左右 24px 的外容器 880px）
         └─ 成果：宽 400px，从工作区顶部开始
```

**硬性规则**

1. **外壳平铺全幅，不再做悬浮白框。** 根容器铺 `canvas` `#FBFBFB`，侧栏使用 `sidebar` 令牌铺不透明的浅石青底，主内容区是贴边的 `surface` `#FFFFFF`；没有外层圆角、没有外边距、没有渐变、没有外壳描边。收起与固定展开态无外壳阴影；只有临时预览侧栏覆盖正文并使用既有 `shadow-overlay`。分区靠底色差异和留白表达，不靠外壳边框。
2. 侧栏不透明浅石青底与主区靠底色差异和留白分开，不加分隔线；临时预览的浮层阴影见 §7。
3. **聊天三栏顶端平齐，消息列自带 56px 头部。** 历史、消息列与成果栏都从 ChatWorkspace 顶部开始并排，没有横跨三栏的外顶栏；ChatTopBar 位于消息列内的 ChatColumn 头部，高 56px、左右 24px。历史收起时头部依次容纳历史开关、搜索、唯一专家选择、当前会话 h1 与操作菜单、右侧成果开关；历史展开时头部只保留历史开关、会话标题与操作、成果开关，搜索与专家选择移入历史栏：历史头部为专家选择 + 新建，其下是既有「搜索全部会话」与列表。窄桌面历史 Sheet 打开时消息头部隐藏搜索与专家选择，Sheet 的 `HistoryHeader` 显示专家选择、新建与关闭，搜索仍在其下；Sheet 关闭后恢复消息头部。专家选择同一时刻只有一处，允许随历史开合切换 DOM 挂载点，不要求前后同一节点或相同 x/y；头部始终位于消息列顶部且高度不变；消息列随分栏开合移动并伸缩，其它子项沿现有 flex 自然排布，不保留空占位。历史默认收起（0），首次展开 240px，可在 200–360px 间拖动并记忆。历史与消息区同用 `bg-surface`（纯白），外部主导航使用 `sidebar` 令牌铺不透明的浅石青底；登录页保持纯白 `surface`，公开分享页铺 `canvas` 画布。消息区左侧历史按钮使用虚线面板图标 `PanelLeftDashed`，右侧会话成果按钮使用镜像的 `PanelRightDashed`；桌面端（`lg` 起）同时显示「会话成果」文字，窄屏保留图标与无障碍名。两者均为常规 32px ghost 按钮，图形比导航的实线折叠图标更轻。右侧会话成果与专家定义文件不同，不展示 `.claude` 配置树；仅展示服务端真实发布的成果，同路径可选择版本，提供静态阅读/源码与下载、基于此版本修改与固定版本分享。成果属于产生它的对话轮次；分享从对应版本的成果面板发起，链接形如 `/s/<shareId>#<token>`，token 只放 URL 片段。无成果显示真实空态，不从回复猜测文件或伪造卡片。该链路已交付，运行验收证据见任务记录。窗口收窄时历史面板仍可收起；面板切换不得清空输入、变更专家或重建消息流。始终仅一个 h1。
4. 对话、欢迎态与 Composer 共用同一条 832px 阅读轴线；含左右各 24px 内边距的外容器最大 880px。Composer 在 ChatColumn 内正常流、始终同一位置、距底 24px，不用 `position: fixed` 覆盖消息。

## 2. 色彩

颜色采用用户选定的石青，字体、圆角、阴影与其他控件外观沿用 Claude Design System（CDS），仅亮色；全部数值来自 `packages/web/src/styles.css` 的 `@theme`，本文不另造色值。系统由中性灰表面阶梯、浅石青侧栏、纯白内容面、alpha 发丝边、深墨文字与石青主操作组成；外壳没有渐变，分区只靠画布与表面的底色差异。

根容器铺画布 `canvas #FBFBFB`，侧栏使用 `sidebar` 铺不透明的浅石青底，具体角色值与映射见 [DESIGN.md 的 Secondary 与 Navigation](../packages/web/DESIGN.md#secondary)；主内容区、页面、会话历史、详情阅读区、卡片与标准浮层统一为 `surface #FFFFFF`，临时预览侧栏仍用浅石青实底。浅色层为 `sunken #F7F7F7` / `hover #F0F0F0` / `chip #F2F2F2` / `selected #E6E6E6`；正文 `fg #202B2E`。主操作走石青 `button-primary #315D67` 三态，按钮键盘焦点环使用独立石青 `ring #4D7079`；通用 `primary #0B0B0B` 保留复选框、Slider 活跃轨道与 line 页签的控件语义。`chart-runs #2A78D6` 只保留为图表数据系列，仅用于数据，不表示导航、按钮、焦点或结果状态。状态色独立表达结果。

### 2.1–2.2 色彩令牌与语义角色

色彩令牌与色值以 `packages/web/DESIGN.md` 的 `colors` frontmatter 与 `packages/web/src/styles.css` `@theme` 为唯一来源，本文件不重复色值。语义角色（用途见 §2.3）：画布/表面/下沉/悬停/chip/选中；主侧栏底面/悬停/选中；正文/辅助/装饰；边线/强边线/控件边界；石青主操作三态、链接、按钮键盘焦点环；状态（成功/警告/危险）与浅底；数据系列；遮罩。

外壳渐变令牌 `shell-start` / `shell-mid` / `shell-end` 与外壳描边令牌已随平铺外壳删除；当前外壳不再使用描边。

### 2.3 使用规则

- **平铺外壳，只靠底色分层。** 根容器铺 `canvas` `#FBFBFB`，侧栏使用 `sidebar` 浅石青实底，主区贴边铺 `surface` `#FFFFFF`；外壳没有渐变、圆角或描边，收起与固定展开态无阴影，临时预览仅复用 `shadow-overlay`。`bg-canvas` 的全局含义仍为 `#FBFBFB`；登录页保持纯白 `surface`，公开分享页铺 `canvas` 画布。
- **导航保持深色文字与图标。** 普通导航文字 `fg`，分组与元信息 `muted-foreground`；主侧栏底面与非选中 hover 使用 `sidebar`、`sidebar-hover`；当前项与找专家卡片共用纯白 `surface`、常态 `shadow-panel` 和 hover `shadow-panel-hover`，配深色 `selected-foreground`，具体角色与深度见 [DESIGN.md](../packages/web/DESIGN.md#navigation)。导航保留原有几何与可见键盘焦点，不增加上浮或装饰性边界；其它导航沿用 `hover` / `selected`。保留当前字重与 `aria-current`，不加彩色竖条。收起态选中仍只落在原图标块。
- **主操作走石青三态。** 普通主操作 `default` 与显式 `solid`（发送、登录）共用 `button-primary` `#315D67`、hover `#284F58`、active `#204149` 的实底与白字；保留现有透明 1px 边框占位、全部尺寸和图标。次操作 `outline`（白底细 `line` 边线、深色字）、`secondary`（`hover` 中性浅填充）、`ghost`（透明，hover/展开中性浅底）与 `plain` 保持各自职责；取消、过滤器、菜单触发器不因主操作换色而变成石青实底。链接用 `link` 深石青 `#2C5660`，保留现有下划线、hover 与可访问名。焦点：输入族（Input / Textarea / Select / Combobox / InputGroup）用 `.cds-focus-glow` 的 1px 中性暖灰边（`subtle #898781`，对白 3.59:1，无光晕）；仅 SourceEditor 与 CodeMirror 搜索用 `input-focus` 浅中性线，按钮类用 `ring` `#4D7079`（按钮键盘焦点环仍为石青，输入框聚焦为中性暖灰），composer 用 `shadow-composer-focus`；状态允许小面积中性呼吸点（见 §11），状态与数据不借用动作色。
- **分段与 line 页签。** 资源页分段控件为 CDS 胶囊轨道：容器 `sunken` 底 + `rounded-pill`、`p-0.5`；当前项为 `surface` 白 thumb + `fg` 字 + `shadow-sm`，非当前项 `muted-foreground`、hover `fg`，不再叠加 hover 底。页签类分段控件容器仍用 `hover`；当前 tab 用 `selected` + `fg`，1px 边框换 `line`，去掉当前 tab 的小阴影。line 页签与二级导航继续透明、不铺底，现有 2px 指示线改为 `primary` 深色，文字 `fg`，位置与宽度不变，focus 独立可见。
- **卡片、表格与列表。** 适合卡片的内容与主侧栏导航选中项共用 DESIGN.md「共享卡片深度」：纯白 `surface`、常态 `shadow-panel` 与 hover `shadow-panel-hover`，必要边界由共享投影承担，不叠加装饰性 outline、ring 或边框。所有业务内容卡复用共享 `Card` 或 `.cds-card-surface`，默认沿用找专家卡片的 hover 上浮、阴影与过渡，不区分静态卡与整体可点击卡；整卡不因视觉反馈新增点击、焦点或 `tabIndex`，内部真实控件与业务状态保留，导航几何保持不变。卡片及其父级滚动容器须保留完整投影与已有交互所需绘制空间，首排顶部与四周不能裁切；具体实现值以真实渲染核对。表格与列表继续使用纯白基底、`line` 分隔、行 hover `hover` 与行选中 `selected`（150ms `--ease-out-soft`，不位移、不加投影；表头与静态行不响应 hover），文字 `fg` / `muted-foreground`，不机械卡片化；输入沿用自身边界契约。Skeleton 用 `sunken`；当前没有共享 Progress 视觉原语，任务进度沿用真实实现；空态与加载态结构不变。
- **可编辑边界单独可访问。** 输入框、Textarea、InputGroup、Select 可编辑触发器与 SourceEditor 使用白底 + 1px `input`（`rgba(0, 0, 0, 0.10)`，等同 `line`）边框；不新增 hover 加深。输入族（Input / Textarea / Select 触发器 / Combobox / InputGroup）聚焦用 `.cds-focus-glow`：1px 中性暖灰边（`subtle #898781`，无光晕）；SourceEditor 与 CodeMirror 搜索仍把边线换成 `input-focus` `#BDBDBD`；composer 文本聚焦由 InputGroup 外框保持 `input` 并换 `shadow-composer-focus`（1px 内环 + 外阴影），不叠加 2px 光环。invalid 保留 `danger` 边框，并用真实 `:focus-visible` 的 2px `ring` outline + 2px offset 补足焦点，错误边框不能代替焦点。未选中的 checkbox/radio 用 `control-boundary`（`rgba(0, 0, 0, 0.35)`），checked/on 用墨色 `primary` 配白色勾/点/thumb，off switch 用 `control-boundary` 与白 thumb。`subtle #898781` 只用于输入族聚焦边，不承担默认可编辑边界；发丝边、`control-boundary` 与 `input-focus` 均低于 3:1，是已接受并公开记录的视觉限制；中性聚焦边对白约 3.59:1。错误、禁用、焦点优先级与形状、尺寸、状态属性不变。
- **消息。** 用户消息由浅蓝底改为 `selected` 中性浅底 + `fg`，保留现有胶囊形状、对齐与宽度；附件用中性 `outline`。助手正文仍在白底上无气泡。
- **浮层与菜单。** 标准浮层使用白表面、`line` 边线与统一 overlay 阴影；临时预览侧栏保留浅石青实底、仅复用该阴影，不加 scrim、不锁焦点。菜单项 hover/键盘高亮用 `accent` + `accent-foreground`，危险项用 `danger` 且不被普通 hover 覆盖；菜单内搜索等可编辑边界用 `input`。Dialog、AlertDialog、Sheet、Popover、Tooltip、Toast 共用同一表面与阴影，遮罩用 `scrim`；tooltip 若既有反色则保留深底白字。确认框的 default 为石青 实底主操作、取消用 `outline`，危险确认保持 `destructive`。Toast 操作按钮用显式 `outline` 中性次操作；Sonner 自带规则特异性更高，允许 toast 根与操作按钮用中性语义令牌做必要的 `!important` 覆盖，不保留旧的蓝色专用覆盖；关闭按钮白底、中性 hover，保留时长、位置、关闭与屏幕阅读器提示。
- **状态与数据不借用动作色。** 成功、警告、失败继续用独立状态色；运行图表首系列用 `chart-runs` 数据蓝，失败用 `chart-failed`（即 `danger`）。OpenUI 图表只把首系列映射数据蓝，其余系列保留既有中性层级与纹理，不扩展分类色板；数据蓝不能蔓延回导航、按钮或焦点。「运行中」状态徽章的 `brand` tone 使用 `selected` 中性底与 `fg` 字，圆点使用 `fg`，保留状态文字与既有动效，不只依赖颜色。
- **代码。** 围栏/块级代码为深色面：表面 `code-block` `#0D0D0C`，正文与语法用浅色 `code-block-fg` `#E6E6E4`，关键字/函数/链接用浅石青 `code-syntax-accent`，注释、参数与标点用暖灰层次，复制反馈 2.5s 后衰减回初始态。行内 `code` 仍是浅 chip `#F6F6F6` 配 `fg` 正文。全局选区以 `button-primary #315D67` 的 22% 与透明色混合，配 `fg` 文字；深色代码块内选区以同一令牌的 38% 与透明色混合，配白色文字。CodeMirror 原生主题走浅色令牌，selection/searchMatch 用 `selected`，gutter `muted-foreground`，搜索面板白底，真实可编辑搜索 input 用 `input` 默认边线与 `input-focus` 聚焦边线。
- **徽章。** default 与 secondary 都是浅中性底、`fg` 字，不再整枚深色填充；outline 仍白底 `line`；危险/成功/警告继续各自语义，链接 badge 保留焦点。文本不借用 `subtle`。
- 所有控件只引用语义令牌（`primary`、`primary-hover`、`button-primary` 三态、`ring`、`selected`、`selected-foreground`、`accent`、`accent-foreground`、`muted-foreground`、`input`、`input-focus`、`subtle`、`link`、`control-boundary`、`chart-runs` 等），不逐页写色值。字体、尺寸、布局与品牌素材不随配色调整改变。
- 保留 hover、active、expanded、checked、selected、invalid、disabled、focus-visible 的真实状态；不能用页面级 CSS 把所有 `bg-primary` 强制改白。状态不只依赖颜色，沿用既有文字、勾选、图标与 ARIA。

正文 `fg` 与辅助文字 `muted-foreground` 在 `surface`、`canvas`、`sunken`、`selected` 及三档侧栏底面上均不低于 4.5:1；状态色在 `surface`、`canvas`、`selected` 上不低于 4.5:1。石青主按钮白字三态均超过 4.5:1，独立 `ring` 对白、画布、选中底与侧栏选中底均超过 3:1。浅色选中填充本身不承担唯一的状态信号，仍保留字重、文字与 ARIA。输入发丝边、`control-boundary` 与 `input-focus` 的既有低对比缺口保留记录，**不得宣称整页 WCAG AA 达标**。半透明边线分别在对应底色上合成，数值不代表浏览器渲染验收；源码再变时须重跑对应页。

## 3. 圆角与实现值

### 对话态

- 消息流最大宽 832px，居中。每轮消息以 `.message-fade-up` 入场（0.4s 上浮淡入，`--ease-overshoot`）；减少动态效果时直接显示。每一轮用户消息是一个独立 `selected` 中性浅底胶囊（右对齐，`fg` 正文），助手回复紧随其后、按轮次成组；轮与轮之间只靠间距分开，不画横线——横线是重复信号，结构已经由胶囊、正文与读数行表达。仍在排队或运行、尚未产出回复的轮次显示「等待回复…」，不留空白；已到终态的轮次显示实际结果或失败原因，不显示等待。

- 工具调用按轮分层：每轮的正常工具调用集中到该轮一个可折叠的「执行过程」区，使用按官方 shadcn `Trace` 源码落地的 `TraceCollapsible` / `TraceLine` / `TraceIcon` / `TraceTitle` / `TraceDescription`，不另写自绘折叠行；折叠头保留单行摘要，展开项沿用单行「图标 + 名称 + 状态 + 耗时」，点击展开参数/结果，不用厚边框。官方 registry 没有独立 Thinking 组件，reasoning 也归 `Trace`；只有事件流实际提供 thinking 数据时才渲染，不伪造。顶层正文的内容与顺序不变，不把正文并入折叠区。审批、原生澄清提问、失败工具、缺失结果与 `error` 始终在折叠区外可见且只出现一次，不从折叠区重复渲染；失败与超时原因常驻显示，不依赖展开。
- 任务清单：当本轮有模型确认的步骤清单时，在助手正文与工具项之后、该轮运行读数之前追加一块紧凑清单，独立于执行过程折叠、不随折叠隐藏，也不复用工具行的展开结构，不做成卡片。标题行只有 16px `ListChecks` 图标与等宽 `xs` 的 `已完成/总数` 计数（常规元信息档），可见计数只出现这一次（屏幕阅读器可另读完整句子），不再另起一行写共 N 项；下面按原顺序列步骤，行距 `gap-1`，步骤文字用 `base` 正文档（14/22）。每步固定 16px 图标 + 文字：已完成用 `CircleCheck` 与成功色、进行中用 `LoaderCircle`（沿用既有旋转）、待处理用 `Circle` 与 `subtle`；完成与待处理文字用 `muted-foreground`，进行中文字用 `fg` 并显示 `activeForm`。状态靠图标形状、文字色与屏幕阅读器的状态前缀共同表达，不只靠颜色。本轮没有确认清单或清单已被清空时不渲染，保留原运行/工具状态行，不出现空态或占位。清单只陈述模型报告的进度，不使用「已完成任务」「全部完成」等质量结论，也不因运行结束改写步骤状态；失败或超时原因仍在该轮常驻显示，不以清单状态掩盖；不新增字号、色值、圆角或间距令牌。
- Composer 在 ChatColumn 内常驻同一位置，沿用分层输入与底部操作布局，保持原有流式跟随、分支、停止和历史恢复逻辑；它位于 MessagePane 之后、距底 24px，不用固定定位覆盖消息。发送是明确动作：新的一轮用户消息出现时视图直接回到最新，即使此前已向上翻看历史；阅读历史期间的流式增量不会抢滚动。
- 输入区提供“添加资料”常规 ghost 图标按钮与多选文件框，已选文件在输入框上方显示名称、大小和移除；类型/数量/合计超限时在输入区内用 `role="alert"` 明确说明，不弹独立面板。正文与附件至少一项即可发送。用户消息把附件显示为紧凑标签（名称、大小，有服务端 id 时整枚可下载）；附件读取/上传失败保留本次选择。不要另做资料云盘、PDF 预览器或拖放/粘贴入口。
- 会话头部参考用户截图：标题用剩余宽度、不足时省略（`truncate`），完整标题保留在 `title` 与可访问文本中，紧随一个常规 32px「会话操作」更多菜单；不把标题拉满整行、不把菜单推到右边。菜单复用重命名、Fork，删除需确认且排队/运行中的会话不可删；未保存的新会话禁用菜单。消息区与会话历史头部都不画底部横线，靠一致的对齐与留白形成整体。历史头部不再显示「对话」等重复标签；桌面历史展开或窄桌面 Sheet 打开时，无论是否已选专家，左侧均为唯一专家选择、右侧为新建会话等历史动作，窄桌面抽屉另有关闭按钮，搜索与列表紧随其下；此时消息列头部只保留历史开关、会话标题与操作、成果开关。聊天没有横跨三栏的外顶栏。
- 历史搜索使用居中浮层，跨全部专家检索会话标题、会话 ID 与消息正文；每条结果同时给出专家、标题、时间与命中的正文摘要，定位信息不另起一行重复。上下方向键移动选中项、Enter 打开，输入法组合期间的 Enter 不触发；Esc、关闭按钮与外部点击走同一关闭路径并把焦点还给触发器。关闭浮层或发起新查询时取消上一轮未完成请求；结果分页使用游标。打开结果后进入目标专家的目标会话并保留当前未发送草稿；只定位到会话，不承诺跳转或高亮正文中的具体命中消息。
- 专家选择在欢迎态与已有消息/历史会话中仍可用，同一时刻唯一：桌面历史收起（`historyCollapsed`）或窄桌面 Sheet 关闭时，无论是否已选专家，唯一 `AgentPicker` 均位于消息列原有的 56px 头部（`ChatTopBar`）；桌面历史展开或窄桌面 Sheet 打开时，唯一 `AgentPicker` 位于 `HistoryHeader` 左侧、与「新建会话」同排；历史开合只切换归属，不复制控件。未发送输入按会话隔离保存到当前标签页的 sessionStorage，刷新可恢复；切换会话不串草稿，新建会话不继承旧会话；切换到另一位专家表示进入该专家的新对话：历史列表按新专家刷新，清空当前视图的旧消息、运行与审批上下文，URL 去掉旧 conversation，回到欢迎态；原会话保留在原专家历史中，未发送输入带过去并继续保留。再次选择同一位专家不清空会话。切换只解除旧事件流订阅，不自动取消后台运行。
- 桌面会话列表默认收起 0；首次展开 240px，之后可在 200–360px 间调整；使用 react-resizable-panels 的 `collapsible`、`panelRef.collapse/expand` 和现有 `useDefaultLayout` 记住布局，收起为 0px，不另建宽度存储。历史与内容使用同一 `bg-surface`，只有 1px 竖向分隔；隐藏时分隔不再占位、历史控件不可聚焦，展开与收起按钮正确交接焦点。标题只在当前可见位置出现，始终一个 h1。

## 7. 侧栏

导航分组固定为：

- **工作**：找专家（`/agents`，工作区首个入口；`/` 按账户权限落到第一个可用入口，无业务权限时进入个人资料）、对话（`/chat`）、频道（`/channels`）、定时任务（`/schedules`）。
- **构建**：资源（`/skills`，四类资源：技能 / 连接器 / 插件 / 知识库）、评估（`/eval`）。
- **运维**：底部独立入口 `/operations`。进入后使用独立导航——概况（原 `OverviewPage`）、运行、运行环境、健康、审计，并提供「返回工作区」；运维不占业务分组。
- **个人**：底部用户信息即入口，不占业务分组。展开显示头像与姓名，收起保留头像入口；两种状态点击都进入 `/personal/profile`，不触发登出，底部入口的可访问名为「个人资料」。进入个人模块后，主导航在 `AppShell` 内把「工作 / 构建」替换为按目的分组的个人六项——**与专家协作**：个人记忆（`/personal/memory`）、记忆提案（`/personal/reviews`）；**工作记录**：我的分享（`/personal/shares`）、使用记录（`/personal/usage`）；**账号**：个人资料（`/personal/profile`）、账号安全（`/personal/security`）——展开 224px、收起 48px 不变。侧栏底部依次为「返回工作区」、独立「退出登录」与账号入口，退出沿用现有登录跳转，不占页头。`/personal` 默认转个人资料。用户可见名称为记忆提案、账号安全；历史 API 术语与路由（`/personal/reviews`、`/personal/security`）保持不变。我的分享表格标题为「我的会话分享」，只列本人会话下未撤销的链接。原 `/memory` 页面已删除，功能迁入个人模块。专家记忆、定时任务与平台凭据仍留原入口；权限不因整合扩大，管理员个人页也只显示本人数据。

参数来源：2026-10-21 CDP 实测；展开宽度按 2026-10-30 用户批准布局更新，收起宽度与水平内边距按 2026-11-07 用户决定收紧。历史浏览器复测只覆盖当时版本，不覆盖当前石青配色、三态交互与本次收紧。

桌面主导航采用 Chrome 式竖直侧栏，状态为 `SidebarMode = collapsed | preview | expanded`：

| 状态 | 侧栏宽度 | 正文让位 | 外壳阴影 |
|---|---|---|---|
| `collapsed` 收起 | 48px | 48px | 无 |
| `preview` 临时预览 | 224px | 48px，侧栏覆盖正文 | 既有 `shadow-overlay` |
| `expanded` 固定展开 | 224px | 224px，推开正文 | 无 |

- 首次无偏好时默认 `collapsed`；已有用户明确固定的展开或收起偏好保留。仅点击固定或收起按钮持久化偏好，hover、键盘焦点与 Esc 不写偏好。
- 收起时鼠标进入或键盘焦点进入侧栏即进入 `preview`；分组标题始终保留布局槽，收起时仅不可见，hover 前后所有导航项的纵向位置与高度固定。鼠标移出且侧栏内无焦点时收回；焦点离开且侧栏无 hover 时收回。Esc 收起临时预览，不改变固定偏好。
- 临时预览点击固定按钮进入 `expanded`；固定展开点击收起按钮进入 `collapsed`。临时预览不加 scrim、不锁焦点；窄桌面沿用现有 Sheet 行为。
- 工作、个人与运维上下文共用上述三态，保留现有分组、路由与权限过滤。

- **展开 224px**，内边距 `16px 12px`，分组间距 18px；过渡 `160ms cubic-bezier(.22,1,.36,1)`，同时过渡 width / height / transform / background-color / box-shadow。
- **收起 48px**，内边距 `16px 8px`；条目变成 32×32 图标块并居中，文字标签 `opacity 0 / width 0`（90ms 过渡），悬停/选中态落在图标块本身而不是整行。
- 顶部：预览与固定展开的品牌区高 32px，显示完整艺术字组合，与右侧固定或收起按钮同高同中心线；收起为 32×32 木工矢量标记。固定与收起按钮均为 32×32、radius 8，不触发 Logo 切图；Logo 切图沿用 §5。
- 「新建会话」位于对话历史头部，为常规 32px ghost 图标按钮；侧栏不设新建会话入口。
- 分组条目高 32px：展开态 radius 8（`rounded-item`）；收起态为 32×32 图标块，radius 6（`rounded-tag`）。
- 普通导航文字用 `fg`；分组标题与账号等辅助入口用 `muted-foreground`。底部用户信息作为个人模块入口，保持现有紧凑样式，展开时头像与姓名靠左，按账号入口而非导航选中行呈现；展开与收起行为一致。账号入口不因个人上下文改外观与可访问名，独立「退出登录」另占一项。
- 侧栏用 `sidebar` 实底，普通条目 hover 用 `sidebar-hover`；品牌标记占位、加载栏与底部入口及 Sheet 内同角色共用侧栏 token，具体映射见 [DESIGN.md Navigation](../packages/web/DESIGN.md#navigation)。不加分隔线，不套外层白框。仅临时预览作为浮层使用既有 `shadow-overlay`。
- 选中态 = 纯白 `surface` + `selected-foreground` 深色文字与图标 + 共享 `shadow-panel` 常态深度，hover 保持白底并换 `shadow-panel-hover`，**没有彩色竖条**，不叠加装饰性 outline、ring 或边框。工作、个人与运维上下文的收起、preview、固定展开与 Sheet 共用 `SidebarLink`；收起态白底与投影只落在原图标块。保留既有圆角、字号、尺寸、位置、可见键盘焦点、`aria-current`、权限过滤与全部状态功能；侧栏底面仍为浅石青，非选中 hover 仍用 `sidebar-hover`。

## 8. 其他页面

## 9. 组件与交互契约

本节是同类 UI 的唯一约定。开发中发现缺口时在此补齐，同时更新共享组件与现有调用方；并行任务沿用相同契约。官方原语负责交互和无障碍，项目令牌负责视觉。**文案与信息密度不在这里逐条规定，统一遵守 §10「信息表达」硬性规约。**

| 场景 | 统一约定 |
|---|---|
| 指针反馈（统一规则） | 按内容面、连续行、控件三层区分，视觉数值（底色、投影、时长与曲线）以 [DESIGN.md「共享交互状态契约」](../packages/web/DESIGN.md#elevation--depth) 为准。**内容面**（卡片、独立瓦片、可拖拽对象）沿用共享卡片契约，hover 换 `shadow-panel-hover` 并上浮，视觉反馈不赋予整面点击语义。**连续行**（表格行、列表行、树行、导航项、菜单项、频道左栏）保持平面，不随卡片上浮；hover 沿用各区域既有底色，表格与列表用 `hover`，主侧栏用 `sidebar-hover`，菜单与页内导航沿用既有 `accent` / `selected` 状态；菜单键盘高亮保持即时，150ms 只约束表格、列表、树行与普通导航项，不强制菜单统一过渡时长；表头行不响应；空态行、展开详情行与无行级操作的表（权限矩阵、趋势明细、检索评估结果等）显式关闭 hover，`DataTable` 数据行保留行 hover 作为扫读反馈；选中继续用 `selected` / `sidebar-selected`。主侧栏选中项是连续行的既有例外：白面配 `shadow-panel` / `shadow-panel-hover`，只换投影、不上浮。**控件**（Button、Toggle、TabsTrigger、分段控件、可点击 Badge）hover 按 variant 换底色或前景；Button 的 active 保留 `.cds-btn-squish` 的 `scale(0.975)` 与 60ms 按压，Toggle、TabsTrigger、分段控件与可点击 Badge 沿用各自选中/按压状态；所有控件都不套卡片上浮，焦点沿用既有 ring 或边界。**输入**（Input / Textarea / Select / Combobox / InputGroup）不响应 hover 抬升，聚焦沿用既有边界与焦点契约。**浮层与容器**（Dialog、Sheet、Popover、Composer、Toast）不响应 hover 上浮，使用各自表面深度。 |
| Input / Textarea / Select / Combobox / 搜索 | 单行高 32px，圆角 8px；多行与多选可随内容增高。默认 1px `input` 发丝边（`rgba(0, 0, 0, 0.10)`，等同 `line`），无 hover 加深、无投影；字段布局通过 Field / FieldGroup 表达 |
| 焦点与边框（统一规则） | 每个控件只允许一层常驻焦点信号，错误态可另加独立 outline：① **有既有边框的输入类**（Input / Textarea / Select 触发器 / Combobox / InputGroup / SourceEditor）→ 输入族普通聚焦用 `.cds-focus-glow`：1px 边框换成中性暖灰 `subtle`（`#898781`，无光晕）；仅 SourceEditor 把那条 1px 边框换成 `input-focus`（`#BDBDBD`）；composer 文本控制器聚焦由 InputGroup 外框保持 `input` 并换 `shadow-composer-focus`；**均不加 2px 光环**。错误态保留危险边框，并用真实 `:focus-visible` 的 2px `ring` outline + 2px offset 补焦点（错误边框不等于焦点）。② **无边框或边框透明的按钮类**（Button / TabsTrigger / Toggle / Switch / Checkbox / Badge / 折叠触发 / 拖拽手柄等）→ 用单层 `focus-visible:ring-2 ring-ring`，并且必须带 `focus-visible:outline-none`（避免叠加全局 `:focus-visible` 的 2px outline）；invalid 时危险边框与焦点环共存，不吞焦点。③ 全局 `:focus-visible` 只作兜底。**例外：已选中的填充控件**（选中的 checkbox / radio / switch 等）填充本身已是深色 `primary`，换边框无法表达焦点，改用单层 `data-checked:focus-visible:outline-2 outline-ring outline-offset-2`（2px 背景色间隔的外轮廓，仍算一层焦点信号）；未选中时沿用各原语既有的单层焦点表达。普通字段标签由控件自身表达焦点，卡片式字段标签统一由外层标签的单层焦点表达。同类填充控件出现时沿用此例外，不得改用 `ring` 叠层。错误边框与焦点外轮廓可同时存在（各表达一种语义，不算叠层）。原则：**输入类的聚焦边界（中性暖灰边或 `input-focus` 浅线）算同一焦点信号**；其余控件边框与光环二者取其一，唯一例外是错误态用 outline 补焦点。实底主按钮（`default` 与 `solid`）聚焦时用单层 `focus-visible:ring-2 ring-ring`，并留 `ring-offset-2` + `ring-offset-background` 的 2px 背景色间隔，invalid 时该 offset 不消失。InputGroup / Combobox 由外框承担焦点，内部输入不重复画框。自动校验：`bun run lint:focus`（已接入手动触发的 CI，检查输入类原语无 `ring-2`、`focus-visible:ring-2` 必配 `outline-none`）。 |
| 错误 / 禁用 | 错误使用危险色边框与字段提示；输入类错误态保留危险边框并用 2px `ring` outline 补焦点，不叠 ring；Field 的 data-invalid 与控件 aria-invalid 同步；禁用同步 data-disabled 与 disabled，保持可读，提交中关闭按钮与取消均不可丢弃请求 |

### 全站页面布局契约

以资源中心（技能·连接器·插件·知识库）与「找专家」页为组件尺寸、间距与操作区基准，以下规则覆盖所有页面。页面按功能组织内容，不另定同类元素的标准。

- AppShell 的 main 是有界工作面，不承担普通页面的整页滚动。非 chat 内容水平 24px、底部 24px，chat 分支保持零 shell padding。对话阅读轴线为 832px（外容器 880px），登录表单是唯一居中窄表单。
- Page 是占满可用高度的有界纵向 flex 工作面，不承担 padding。PageTopbar 把页头、资源导航、任务页签与页面全局搜索筛选组成常驻顶部组（内部 gap 12px）；PageBody 承担正文纵向滚动。顶部组与正文之间 16px（Page 根 gap 16px），PageBody 内部区块间距仍为 24px，显式 `gap-0` 的对话与 `gap-8` 的登录继续使用原有间距。聊天与频道对话、角色矩阵、文件阅读器保留自身滚动容器；公开 login/share 页面保持自然文档滚动。
- PageHeader 单行最小高 48px（`min-h-12`）、不另加顶部或横向 padding，左侧标题，右侧常规 32px 操作，操作间距 8px；sr-only 页头完全脱离正常流。指标与多层读数另放正文；单行的范围或口径说明可写在 PageHeader description，筛选放顶部组的下一行，不把多层读数塞进标题行。
- PageHeader 与 PageToolbar 自身不使用 sticky，常驻位置由 PageTopbar 与正文分区实现。PageToolbar 自身 `gap-2`（8px）、控件内部间距 8px、可换行，不额外加 padding 或高度；搜索桌面 224px 且可收缩、筛选 144px、排序 128px。使用正常布局间距，不写负外边距补偿。
- PageSection 内部间距 16px，区块分隔后顶部 20px（`pt-5`）。运维·概况用于摘要与异常定位，运行默认卡片并支持切换表格，审计保持数据表，评估与健康按功能分区，详情保留步骤与检查器，不机械卡片化。
- 运维·概况只保留一套日常概览：统计窗口说明放在指标组标题处一次，概况、专家指标和趋势统一使用最近 7 个 UTC 自然日（含今天）；四张卡片为运行次数、运行成本、专家、连接器，连接器数量只含资源中心可管理项，卡片内不再重复窗口；不再另设任务总数看板或快捷入口。待处理事项（审批与失败运行）合并为唯一入口，空态给下一步动作，不写“暂无”。正常健康指标不占业务入口，仅当前队列积压/等待、指标缺失或刷新失败时显示一行并链接健康页；队列历史 failed 是保留计数，只在健康页解释。主区展示带整数运行次数刻度的运行趋势与最近运行；趋势提供可键盘展开的同源数据表，日期、运行、失败、成本与 token 均可读取，表格仅在容器内横向滚动。完整专家数据放下方，专家名称直接链接对应详情。概况数字不与导航按钮混排，长列表不得把关键入口挤出首屏。
- 窗口收窄时保持无页面横向溢出；两列功能区在空间不足时顺序堆叠，表格必要时只在表格容器内水平滚动。所有加载、错误、空态与正常态沿用同一骨架，始终一个 h1。
- 页头操作使用常规 default/outline，区块与行内操作使用 sm；应用页面不为同种按钮覆盖圆角、高度与焦点。聊天输入区的页面级规格只采用 §6 已定义值。

### 固定视觉值与场景例外

- §1–8 的布局尺寸与间距以本文工程规约为准；配色、字体、圆角、阴影与组件外观按 `packages/web/DESIGN.md`（视觉权威），精确实现值以 styles.css 的语义令牌为准。
- `subtle`（`#898781`）保留给装饰细节、次要状态图标与禁用例外；表头、时间、计数、帮助文字、错误恢复说明与可操作标签使用 `muted-foreground`（`#505F63`，见 §2）或 `fg`。`subtle` 不用于承载需要阅读的信息；`muted-foreground` 辅助文字保持至少 4.5:1 对比度（见 §2.4）。禁用状态保留其既有例外。
- 控件沿用桌面字号：Input / Textarea 使用共享 13px 语义字号；多行代码编辑器可保留等宽排版，但不关闭浏览器缩放。
- 聊天继续使用 832px 阅读轴线与多行输入区；运行默认卡片并支持切换表格，审计、评估结果使用数据表；资源中心的内资源使用紧凑列表或数据表（技能 / 插件 / 知识库列表、连接器 `DataTable`），技能市场使用轻量条目列表。统一的是令牌、控件与状态反馈，不是这些场景的布局形态。

### 可访问交互与异步状态

- 表格保留可识别的行、列与表头关系；排序暴露当前方向，长值可换行或在详情中完整读取。窗口收窄时只滚动表格容器；列排序同时提供拖拽、键盘与点击调整路径，锁定列不能被历史偏好隐藏。
- 页面标题、弹层标题、说明和下拉选项允许长文本换行。弹层头部保持可达，内容区受动态视口高度约束并隔离滚动。Popover（包括表格列设置）通过 Base UI 的 `--available-height` / `--available-width` 限制可用空间，超长内容内部滚动并设置 `overscroll-contain`；这是短视口适配，不改变固定控件尺寸与圆角。
- 保存期间禁用受该请求影响的表单字段及冲突操作，字段同步 `data-disabled`。同一 pending 标识只能管理一个在途请求；要么串行禁用，要么按对象分别跟踪。乐观更新不得通过卸载/重建确认框清除请求保护。拥有弹窗或编辑子树生命周期的父层在真正卸载前结算 pending 与阻塞导航 resolver，不依赖子组件卸载清理或 per-call mutation 回调。已有缓存数据时，后台刷新失败保留同一编辑子树并提供真实错误与重试；只有首次无数据失败才整块替换。
- 校验在提交时明确显示字段错误并关联控件；数字显示数值边界，列表显示项数，文本显示字符数。键值与 JSON 编辑不得静默丢弃无效内容；必填错误需给出补全路径。
- 原生澄清提问放在对应工具调用位置，以问题、选项与回答动作组织；复用单选、复选与文本输入，提供「其他」及「暂不回答」。已回答/关闭状态只读；运行详情复用同一组件。提问回答不表达业务工具已获批准，不与审批动作混用。
- 状态不只靠颜色表达；消息需提供发言者语义，审批需准确对应连接器与工具。辅助数据失败也应显示重试入口，缺失指标不得伪装成零；ResourcePage 的资源数量仅在列表请求成功时显示，加载或失败时显示相应状态。等待提示只属于仍在排队或运行、尚未产出回复的任务；已失败或已超时的任务保留实际结果与失败原因，不得提示仍在等待。
- 会话切换使旧请求与事件流失效，晚返回响应不得覆盖新会话；历史尚未加载完成时不能追加发送。连接中断不是任务终态，保留运行标识与停止入口，并从服务端状态收尾。输入法组合输入的 Enter 不触发发送。
- 错误 toast 保留到主动关闭；复制失败提供手动复制说明。焦点提示不得被页面覆盖移除，关闭弹层返回实际触发器，触发器消失才使用后备入口。
- 登录状态检查期间的全局骨架与失败分支也保留当前路由的单一 `PageHeader`（可视觉隐藏）和文档标题；未知路由明确命名为「页面不存在」。
- `DialogShell` 中的表单提交校验失败后，等待字段错误渲染，再聚焦内容区首个 `aria-invalid` 控件并滚动到该字段；复杂专家 Sheet 继续由分区导航定位错误，避免把隐藏分区当作可见表单。
- 强制颜色模式下，控件阴影焦点会被系统移除，统一恢复系统 `Highlight` 的 2px 轮廓；这是系统可访问性适配，不改变普通模式的按钮石青 `ring`、输入中性聚焦边与既有布局值。
- 多选 Combobox 的已选项区域有分组名称，每个移除按钮明确命名「移除 + 项目名」；Chip 与输入提供 Base UI 的方向键、Backspace / Delete 操作说明，不能只给外层 Chip 命名。
- 编辑草稿必须与打开时的版本基线绑定。409 冲突不得自动用最新版本号重发旧草稿；提供明确的重新加载动作并确认放弃旧草稿。dirty 或保存中也保护路由离开与刷新，不能只保护弹层关闭。
- 键值编辑拒绝重复键并指出行号；环境变量区分大小写，HTTP Header 不区分大小写。后端不支持清空的可选配置不得显示可保存的「恢复默认」或把空值伪装成保存成功。
- 历史会话重开需等待最新历史并恢复最近运行与审批上下文；运行进入终态时最后刷新一次审批，再停止轮询。发送被接收后刷新服务端会话列表；只保存批准的按钮命名为「批准」，不承诺自动继续运行。
- 评估跑批中断原因与已完成结果同时显示，部分通过不得掩盖未完成用例；登录凭据错误与会话失效分别提供恢复说明。

- 页面身份按实际匹配路由确定；命中 `$` 的未知地址即使带有已知路径前缀，也统一显示「页面不存在」文档标题和加载/失败标题。
- 专家回滚与常规保存共用 pending 生命周期；回滚确认明确说明未保存草稿会丢弃，等待期间不可关闭历史、继续编辑或离开路由。版本差异须完整显示目标文本与数组内容，导入返回的提示须可逐条阅读。
- 专家配置的任务切换与路由离开共用同一份 dirty/pending：主配置草稿与当前子面板（记忆 / 规则 / 输出风格）的未保存内容都算数。主配置随页面常驻，切换任务保留草稿；子面板草稿会随任务卸载，切换前确认放弃。路由离开两种草稿都要保护，保存中不得切换或离开。各子面板的保存只负责自身资源，配置保存按钮不跨任务保存。
- 聊天离开页面保留未发送输入，清理会话和运行上下文；历史终态恢复结果与失败原因，未被服务端接收的发送不显示指向旧运行的「本次运行」。连接器名称缺失时审批显示其 ID。
- 运行列表沿用当前接口的最近 100 条范围，范围与「排序仅作用于当前显示的记录」写在 PageHeader description；不承诺接口尚未提供的完整历史分页。

## 10. 信息表达（设计规约·硬性）

> **一句话：删掉标语、辅助文案和次级标签。"Cut taglines, helper text and secondary labels. If a screen needs them to make sense, fix the layout."** 界面必须靠这些文字才看得懂时，先改布局，而不是补文字。
>
> 这是每个页面、区块、卡片、弹层的**默认约束**，不是建议。视觉做得再对，只要靠一堆次级标签和说明文字来解释结构，就算没遵守本规约。评审 UI 时先过这一节。
>
> 布局与文案调整同时遵守 [AGENTS.md「决策标准」](../AGENTS.md#决策标准) 的 UX/DX/AX 原则，并保留现有功能。

### 10.1 核心规则

1. **结构先由布局承担。** 先用分组（group）、对齐（alignment）、间距（spacing）、层级（字号/字重/底色）表达关系。若当前布局表达不了某个关系，**先改布局**（分组、对齐、间距、标题层级、容器边界），不要用加文字当补丁跳过这一步；确认布局确实无法承载后，才补必要的文字（见 10.2）。
2. **不重复解释。** 页面标题、分区标题、字段标签、占位符、徽章、计数、可见控件已经表达的信息，不得再用副标题、行内说明或第二次标签重复一遍。
3. **文字只为「新信息」存在。** 一段可见文案必须二选一：给出布局无法表达的新信息，或指导下一步操作。两者都不满足就删掉。
4. **信息层级 = 层级信号，不是满屏小字。** 用少量强信号（容器边界、一级标题字号/字重、两列对齐）分层；不要给每个字段都挂一行灰色小字，那会把层级摊平成噪音。
5. **空态/错误/加载也遵守。** 空态按首次无数据、筛选无结果、无权限三类原因，分别写「一句事实 + 一个动作」，不复述「暂无/还没有」，也不用口号；列表空态用无框 `PageNote`，`EmptyState` 默认无外框；错误给可恢复动作；加载给共享骨架。不写承诺式废话。
6. **删词不等于删信息。** 实现细节类信息（落盘路径、字段映射到哪个文件）**一次讲清即可**——放进「完整文件」页签、展开区或 tooltip，不在主界面逐项重复。

### 10.2 允许保留的文字（不可为"精简"而删除）

- 表单字段标签、必填标记、格式/约束提示（如「创建后不可修改」）。
- 校验错误、禁止/危险操作说明（如「此操作不可撤销」「放行内置工具会扩大攻击面」）。
- 影响决策的安全/权限信息、状态与结果（步骤、状态、耗时、工具 IO、审批与实际执行对应关系）。
- 无障碍名称、`aria-*`、`sr-only`、按钮/链接文案、placeholder。
- 空态里的**下一步动作**与其按钮。

> 精简可见文案时，交互原语的无障碍契约（标签、名称、状态播报）仍须满足，见 §9 与「可访问交互与异步状态」。

### 10.3 优先做法（用这些代替加文字）

| 想表达 | 用布局 | 不要用 |
|---|---|---|
| 字段属于哪一组 | 分区标题 + `FieldGroup` + 间距 | 每个字段旁贴分组名/路径标签 |
| 谁更新、什么时间、什么状态 | 对齐的列/徽章/时间戳 | 行内叙述「该记录于…更新为…」 |
| 数量/汇总 | 徽章、计数、列、指标卡 | 另起一行「共 N 个…」重复 |
| 层级关系 | 容器边界（卡片 vs 画布）、字号/字重 | 到处加同色小号说明字 |
| 空态引导 | 标题 + 一个动作；同屏已有主操作时，重复入口用 outline sm | 「这里还没有任何内容，请先去 X 添加」 |

### 10.4 反模式（出现即改）

- 页面级副标题只是把路由名/标题再说一遍。
- 卡片/行下方再挂一行复述可见控件、类型或数量的小字。
- 逐字段 `→ 某文件路径`、`仅运行时` 之类落盘/实现标签贴在表单上。
- 空态写「还没有/暂无…」+ 一大段说明或口号，却不按原因给一句事实与一个动作。
- 同一个计数既在徽章又在旁边文字里出现。
- 用次级说明去弥补层级不足，而不是改分组/间距/标题字重。

### 10.5 提交前检查清单（逐条对照）

- [ ] 删掉任意一行可见说明后，界面是否仍然清楚？是 → 删掉。
- [ ] 每个可见副标题/说明是否都在提供**新**信息或**下一步**？否 → 删掉。
- [ ] 层级是否靠分组/对齐/间距/字号区分，而不是靠更多灰色小字？
- [ ] 空态是否「是什么 + 下一步动作」，没有复述「暂无」？
- [ ] 实现细节（路径、文件映射）是否只讲了一次（放完整文件/展开区/tooltip）？
- [ ] 删除文案后，字段标签、`aria-*`、`sr-only`、错误与危险提示是否完整？否 → 补回。

## 11. 动效

- 本项目 `@theme` 动效曲线：`--ease-out-soft` = `cubic-bezier(0.16, 1, 0.3, 1)`（对齐 CDS `ease-swift`，交互/悬停主曲线）、`--ease-out` = `cubic-bezier(0.165, 0.84, 0.44, 1)`、`--ease-overshoot` = `cubic-bezier(0.34, 1.3, 0.64, 1)`、`--ease-pulse` = `cubic-bezier(0.4, 0, 0.2, 1)`；CDS `ease-enter` 同值曲线（`cubic-bezier(0.22,1,0.36,1)`）仍用于侧栏、品牌切图与聊天工作区的 Motion 配置；其余参考曲线（`ease-expand`/`ease-snap`/`ease-pop`/`ease-rise`/`ease-fall`）暂未接入。
- `@theme` 时长令牌为 `--dur-fast` 60ms 与 `--dur-slow` 0.45s；CDS 参考阶梯 `--dur-snap` 120ms / `--dur-base` 200ms / `--dur-sheet` 300ms 按场景在 utility 内联。只过渡实际变化的属性，禁止 `transition-all`。
- 按钮按压走 15 阶物理弹簧 `--btn-spring`（`linear(0, 0.2459, … 1)`），active 时 `scale(0.975)`；`.cds-btn-squish` 把 `transform` 绑定到 `--dur-slow` + `--btn-spring`，颜色、背景与边框走 150ms `--ease-out-soft`，`:active` 的 transform 仍走 60ms `ease-out`。弹簧按压允许出现在所有共享 `Button`。
- 侧栏宽度过渡 160ms；标签淡出 90ms；预览与固定展开状态 Logo 切图为 300ms 轻推接力；品牌标记与固定/收起控件切换沿用 140ms 过渡。
- 允许的动效：局部交互与状态反馈（悬停背景、展开折叠、浮层显隐、流式光标、复制/安装结果）、消息入场 `message-fade-up`（0.4s、`--ease-overshoot`）、卡片 hover 上浮 1.5px（200ms、`--ease-out-soft`）、执行过程展开 `timeline-expand`（200ms、`--ease-expand`）、滚动遮罩 `scroll-fade-y`（上下 28px 渐隐）、等待点 `quiet-dots`（1.9s、`--ease-pulse`）与状态呼吸点（`dot-pulse` 1.2s）、普通输入聚焦换中性暖灰 1px 边。
- 浮层（Dialog / Sheet / Popover / 菜单 / 选择器 / Combobox / Tooltip）统一由 `.cds-overlay-enter` 驱动 `opacity` + `scale(.96)` → `1` 的过渡（200ms、`--ease-out`），Base UI 的 `data-starting-style` / `data-ending-style` 在动画结束后卸载；Positioner、Portal、焦点与关闭保护保持不变。
- Sheet 保留各 side 的定位与尺寸，仅淡入淡出，不做位移；Switch、加载/运行状态等控件必要状态保留其原有位移或颜色过渡。
- 骨架屏允许 `cds-skeleton-sweep` 扫光；消息滚动按钮只做可见性淡入淡出，不位移、不缩放。
- 减少动态效果（`prefers-reduced-motion: reduce`）下全局把动画/过渡时长设为 `0.01ms`、延迟 `0ms`、迭代 1 次，`scroll-behavior: auto`；JS Motion 仍由各调用方读取 `useReducedMotion` 自行收敛。

## 12. 实现技术栈（硬性）

视觉由 `packages/web/DESIGN.md` 与 styles.css 令牌决定，交互与结构由下列库决定。**不得手写这些库已经提供的东西**：

| 需求 | 唯一实现 | 约束 |
|---|---|---|
| 控件、表单、浮层 | shadcn/ui（`base-nova`）+ Base UI | 先复用或安装官方组件，共享视觉由 `@theme` 语义令牌控制 |
| 图标 | lucide | `LucideProvider` 在 `App.tsx` 统一设 `strokeWidth={1.75}`、`size={16}`，组件里不要再逐个传 |
| 动效 | Motion（`motion/react`）+ Base UI 状态过渡 | 局部交互与状态反馈用 CSS transition（常用 150ms，60–200ms 阶梯、`--ease-out-soft`；浮层用 `data-starting-style` / `data-ending-style`）。需要布局开合时用 Motion：`duration` 沿用 §11 与现有实现的固定值（折叠/浮层 0.15、侧栏 0.16、品牌切图 0.3），缓动 `--ease-out-soft` 或 `easeOut`，并读 `useReducedMotion`；消息入场 0.4s 只使用现成工具类，不扩散到布局开合 |
| 可拖拽分栏 | react-resizable-panels v4 | `Group` / `Panel` / `Separator`；用 `useDefaultLayout` 持久化；分隔条就是 1px `border-line`，不加把手 |
| 拖拽排序 | dnd-kit | 必须带 `KeyboardSensor`，拖拽手柄有可访问名称 |
| 客户端状态 | Zustand | 只放**跨组件、非服务端**的状态；服务端数据一律 TanStack Query |
| 路由与 URL 状态 | TanStack Router | 筛选、分页、选中的 tab 走 `validateSearch`，不要塞进组件 state |
| 类名合并 | `cn`（`lib/cn.ts`） | 唯一实现，不引入 clsx / tailwind-merge 的第二份 |
| 生成式 UI 渲染 | `@openuidev/react-lang` 的 `<Renderer>` | 组件实现全部映射到 shadcn/ui；官方解析、响应式、表单与Query/Mutation运行时负责交互。业务不加载 `@openuidev/react-ui` 的视觉层，该包仅作开发期契约对照。围栏外散文仍走Markdown |

- 项目圆角：卡片 12 / Composer 14 / 用户消息气泡 12 / 行与常规控件 8 / 32px 图标按钮 8（共享 `size="icon"` 32px / `icon-lg` 36px 与紧凑、侧栏折叠实例一致）/ 紧凑图标按钮 8 / 标签 6；外壳平铺、无外框圆角。底座内部细节沿用官方结构；`--radius` 为 8px；InputGroup 的内部按钮与 addon 采用 8px 图标圆角档。共享映射见 `styles.css`。
- shadcn 原语的语义色（`bg-popover`、`text-muted-foreground`、`bg-accent` 等）已全部映射到统一语义令牌，**不要在组件里改回具体色值**。
- shadcn 定制顺序：内置 variant → 局部布局 → 源码中的语义 variant → 有实际复用需求的应用组合。底座组件放 `components/ui/`，应用组合放 `src/components/`（如 `ConfirmDialog`）。允许改源码，但保留原语的 `aria-*`、焦点管理与键盘交互，只改外观 token；安装/更新前对比 git diff，`--overwrite` 会覆盖既有定制。

## 13. 禁止

- 卡片套卡片、彩色边框、彩色左边条。
- emoji 当图标。
- 一页多个同等权重标题。
- 在组件或页面里写死 hex、rgba 或第二套颜色表；所有颜色只从 `styles.css` 的 `@theme` 语义令牌取。
- 把 Logo 的黄色或木色铺成高饱和度的大面积页面、按钮或选中态；不得为各页面另造强调色。主操作只走石青三态，数据蓝只用于 `chart-runs`。
- 把普通图标、正文或整片界面染成石青或数据蓝；石青强色属于主操作与按钮键盘焦点，正文链接使用既有深石青 `link`；主侧栏仅允许 [DESIGN.md](../packages/web/DESIGN.md#secondary) 定义的浅石青背景角色，不扩展到图标、文字、状态、数据或危险色。状态不借动作色，运行中徽章用 `selected` 底与 `fg` 字，圆点用 `fg`，保留状态文字与既有动效；数据蓝只属于图表数据。
- 用次级标签/说明文字去重复布局、标题或控件已经表达的信息（违反 §10）。
- 在 CDS 双环浮层阴影（含临时预览侧栏）、Composer 三态阴影与共享卡片 `shadow-panel` / `shadow-panel-hover` 之外另造平行阴影，或给这些表面追加装饰投影、彩色光晕；共享卡片保留既有深度，收起与固定展开侧栏保持无阴影。大面积装饰渐变与玻璃同样禁止（滚动遮罩、骨架扫光等状态渐变除外）。
